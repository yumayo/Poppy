# WSLプロジェクト

「＋ Open folder」またはCtrl+Oから「Open WSL folder…」を選ぶと、エクスプローラーと同じWindows標準のフォルダー選択が開きます。初回は`\\wsl.localhost`（古いWindowsでは`\\wsl$`）からディストリビューションとフォルダーを辿って選べます。アドレスバーへ`\\wsl.localhost\Ubuntu\home\user\project`のようなパスを貼り付けることもできます。次回は前回の選択場所を開き、Windows用のフォルダー選択とは履歴を分けて保持します。

「WSL user (optional)」を空欄にすると、そのディストリビューションの既定ユーザーで接続します。別のユーザーで接続する場合はユーザー名を入力してください。フォルダー選択中の参照権限はエクスプローラーと同じです。Windowsプロジェクトと同時に開けます。

`Poppy.exe '\\wsl.localhost\Ubuntu\home\user\project'`のようなコマンドライン指定と、Windowsのフォルダー選択で受けた`\\wsl$\Ubuntu\…`もWSL接続へ変換します。通常のSMB共有はWindowsプロジェクトとして扱います。

接続中・接続済み・切断・利用不可はプロジェクトの補助表示とツールチップで確認できます。接続に失敗したらF5、またはプロジェクトの右クリックからReconnectで再試行します。未保存の本文は切断後も保持し、接続が戻るまで保存・名前変更を開始しません。非選択のWSLプロジェクトは、再起動時には構成だけを復元し、選択するまで起動しません。

## 使える機能

- ファイルツリー、Ctrl+P、通常表示、編集とCtrl+S、F2によるファイル・フォルダーの名前変更。
- Ctrl+Fによるファイル内の文字列検索。未保存の本文を含め、追加のWSL通信なしで検索します。
- Ctrl+Shift+Fによるプロジェクト内の全文検索。保存済みファイルはLinux側で並列に走査し、一致箇所だけをWindowsへ送信します。未保存ファイルはエディター側の本文を使います。[検索の実装と設計](search.md)を参照してください。
- WSL側のGitによる変更一覧・差分。Gitがない場合や所有者の検証に失敗した場合は、Gitサイドバーに理由を表示します。
- 同じディストリビューション・ユーザー・Linuxディレクトリでのターミナル起動。ログインシェルはLinuxユーザーの設定を使います。左右分割・タブの移動でシェルを再起動しません。
- inotifyによる外部更新の検知。通知の不足・監視上限・`/mnt/`では再検証も要求します。F5と再選択時の再検証も利用できます。
- プロジェクト、タブ、左右の所属・選択、表示位置、ターミナルのcwdの保存と復元。

`A.cpp`と`a.cpp`、Unicodeの合成形、名前に含まれるバックスラッシュは別の名前として保持します。検索の絞り込みは大文字小文字を無視しますが、開く対象のパスは変換しません。UTF-8で表せない名前はエスケープ表示し、開く操作・編集・名前変更を無効にします。

ファイル本文は16 MiB、デコード後も16 MiB・100万行未満が上限です。Ctrl+Pの一覧は最大20万ファイル・5万ディレクトリです。リンクのディレクトリを再帰走査しません。Windowsの関連付けアプリで開く操作はWindowsプロジェクト向けです。WSLのファイルはWSLターミナルから必要なアプリで開いてください。

## 保存と名前変更

保存では、読み込み時のファイル情報と内容のSHA-256を照合し、同じ親ディレクトリの一時ファイルをfsyncしてから置換します。元の文字コード・BOM・改行、所有者・グループ・modeを維持します。検出した外部変更があれば保存を拒否し、編集内容を残します。

ファイルへのシンボリックリンクはリンク先へ保存します。複数のハードリンクがあるファイル、別ユーザー所有、setuid/setgid、ACL・拡張属性がある場合や、属性を維持できない場合は保存を拒否します。管理者権限への昇格は行いません。外部アプリと共有する比較・置換APIはないため、最終確認と置換の間の競合を完全に排除するものではありません。

名前変更はLinuxの規則とファイルシステムのNAME_MAXを検証し、`renameat2(RENAME_NOREPLACE)`で既存ファイルへの上書きを防ぎます。この操作を利用できない環境ではエラーを表示します。成功後は未保存の修正を保ち、配下のタブ・ツリー・次回起動するターミナルのcwdを追従させます。

保存・名前変更中に接続が切れた場合は自動再送しません。再接続後にディスクの状態を確認し、外部変更との競合を解消してから保存してください。

## 配布とビルド

Windows x64とLinux x86_64の組み合わせを対象とします。WSLの登録済みディストリビューションと、`--list --quiet`・`--distribution`・`--exec`を利用できるwsl.exeが必要です。Linuxのローカルユーザーを`/etc/passwd`から確認します。ARM64・NSSだけで定義したユーザーには対応していません。

配布する構成は次のとおりです。

```text
Poppy.exe
ai/                       # 既存のWindows用ai-containerアダプター
wsl/
  poppy-wsl-helper        # Linux x86_64の静的リンク実行ファイル
```

Dockerの`make artifact`はLinuxヘルパーもビルドし、`out/docker/wsl/`へ出力します。`docker/build.sh`を変更したため、既存のビルドコンテナではホスト側で`make dev`を実行して固定スクリプトを更新してください。

Windowsで直接ビルドする場合は、Linux x86_64環境で先に`poppy-wsl-helper`ターゲットをビルドし、WindowsのCMakeへ`-DPOPPY_WSL_HELPER=C:/path/to/poppy-wsl-helper`を渡してください。指定しない場合もWindowsプロジェクトは利用できます。WSL接続時にヘルパーが見つからなければ、必要な配布フォルダーを案内します。利用者のWSLでのコンパイルやダウンロードは不要です。

初回接続は固定のブートストラップ処理で、配布済みヘルパーを標準入力から送り、`$HOME/.local/share/yumayo/Poppy/helpers/<version>-<sha256>/`へ配置します。所有者・書込権限・シンボリックリンク・SHA-256を確認し、一時ファイルから置換します。再接続では検証済みの同版を再利用します。配置には`/bin/sh`と一般的なcoreutilsが必要です。

ファイル通信は長さ付きフレームの標準入出力だけを使い、ポートを開きません。接続はディストリビューションと要求ユーザーごとに共有し、要求ID・プロジェクトID・世代を検証します。軽い操作は10秒、Gitは20秒、索引作成は60秒で応答を待つ上限を設けます。全文検索は結果を順次受信し、最大10分で検索だけをキャンセルします。通常の取消しも随時受け付け、2秒以内に終了を確認できなければ既存の接続切断処理を使います。検索はファイル・Git操作と別の処理枠で実行します。送信待ちは1 MiB、受信中の本文・一覧は接続ごとに64 MiB、検索結果は最大2,000件・概算2 MiB、監視は8,192件が上限です。

最後の接続を閉じるとヘルパーへshutdownを送り、猶予後に対象プロセスを終了します。ターミナルは専用のLinuxプロセスで子孫を監督し、同じUIDだけが接続できるセッション固有のローカルIPCで終了と後始末を確認します。`wsl --shutdown`やディストリビューション全体の停止は行いません。

## AI CLIと通知

WSLプロジェクトのターミナルの「＋」を右クリックすると、WSLにインストールしたCodex・Claude Codeを直接起動できます。Windowsプロジェクトの既存ai-container起動は従来どおりです。WSLのLinuxパスを既存のWindows用ai-containerランチャーへ渡す接続は未実装です。

通知IDとURLは既存の`WSLENV`を保って引き継ぎます。通知には利用するCLIのhook設定と、WSLから到達できるWindowsの通知先が必要です。WSL2のNAT環境などでWindowsの127.0.0.1へ到達できない場合は、既存の`POPPY_HOOK_HOST`設定を利用してください。ファイル接続に伴って通知の待受やファイアウォールを変更する処理はありません。[AI連携](../integration/ai/README.md)も参照してください。

## 検証範囲

Linux上の単体テストは、authorityの分離、ケース・Unicode・バックスラッシュの保持、UNC別名、ファイル名、UTF-16のディストリビューション一覧、分割フレーム、不正JSON・長さ・部分受信、SHA-256を確認します。保存テストはアプリDB 2→3・プロジェクトDB 6→7の移行、Windowsの保存先の維持、WSLごとの分離、左右分割・UID・POSIXパスの復元、ロールバックを確認します。

Linuxヘルパーの結合テストは、実際のパイプ、固定ブートストラップ、初回配置・再利用・破損時の再配置、通常・空・最大サイズ・UTF-16ファイル、FIFOの拒否、属性・リンク、外部更新の保存拒否、名前変更の衝突、inotify、Git引数と取消し、EOF・不正フレーム、2つのPTYの独立した終了を確認します。全文検索ではPOSIXの名前・大文字小文字を保つ結果の分割送信、除外規則、未保存パスの除外、件数上限、実行前の取消しと接続の再利用を確認します。実Gitの結合テストはビルド環境にGitがある場合に実行します。

Windows版とWindows用の既存テストはクロスコンパイルで確認します。Windows + WSLのGUI、ConPTYと実シェルの組み合わせ、WSL1・WSL2・DrvFsの差、AI通知の到達性、性能値は実環境で別途検証が必要です。
