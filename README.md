# Poppy

Windows専用の、AI CLIと一緒に使う小さなコードエディターです。左端にプロジェクト一覧、その右にアイコンだけのアクティビティーバーとエクスプローラー／Gitのサイドバー、さらに右に編集可能なコード表示、右下にターミナルを配置します。AIに編集を任せながら、人間による小さな修正も行えます。

C++17 / Win32 / Direct2D / DirectWrite / ConPTYで実装し、ブラウザー、WebView、Node.js、.NETランタイム、エディターエンジンを常駐させません。LSP、拡張機能は入れていません。

コードビューアー、ターミナル、ツールバー、タブ、ファイルツリー、Git一覧、アクティビティーボタン、スクロールバーをDirect2Dで描画し、文字の整形とフォントのフォールバックはDirectWriteを使います。アイコンはDirect2Dのベクターパスを使い、図形のアンチエイリアスと丸い線端・結合で滑らかに描画します。ツリーとボタンも独自のウィンドウで描画し、アプリからGDIの描画・フォントAPIを呼び出したり、`gdi32`へ直接リンクしたりする処理はありません。描画テストのビットマップにはWICを使います。スクロールバーはアプリの暗いテーマに合わせ、通常・ホバー・ドラッグ中の色を切り替えます。メニュー、ツールチップはWindowsが描画する標準UIを使います。

コードとターミナルは全角文字を含めて固定セルの位置に描画します。ウィンドウの描画先はハードウェア描画を優先し、作成できない場合はDirect2Dのソフトウェア描画を使います。リサイズとモニターごとのDPI変更に対応し、描画リソースの喪失時は描画先を再作成します。Direct2D、DirectWrite、WICはWindowsに含まれるため、配布用の追加ランタイムは不要です。

**初期実装です。Windows上での動作、実際のAI CLIとの互換性、メモリ使用量は未検証です。** Docker上でのWindows向けクロスビルドとLinux用コアテストは実行済みです。メモリ使用量の達成値は記載していません。

## ビルド

生成するアプリはWindows 10 version 1809以降のx64環境が対象です。WindowsプロジェクトのGit表示には、別途Git for WindowsをPATHに追加してください。WSLプロジェクトは選んだディストリビューションのGitを使います。AI CLIも利用する環境へ別途インストールします。

状態の保存にはSQLite3を使います。SQLite3はC++標準ライブラリには含まれません。`third_party/` はGit管理対象外のため、ビルド前に [SQLite公式サイト](https://sqlite.org/download.html) の `sqlite-amalgamation-*.zip` から、同じリリースの `sqlite3.c` と `sqlite3.h` を `third_party/sqlite/` に配置してください。SQLite 3.54.1でビルドと保存テストを確認しています。CMakeで静的リンクするため、配布先にSQLiteのDLLを追加する必要はありません。

### Dockerでビルド

GNU Makeを用意し、Docker DesktopをLinuxコンテナモードで起動して、リポジトリのルートで実行します。ホスト側のVisual StudioやCMakeは不要です。

```sh
make dev
make artifact
```

`make dev`は`docker compose up -d --build dev`を実行し、`poppy-dev`コンテナを常駐させます。Dockerの再起動後も自動起動します。明示的に停止した場合は`make dev`で再開できます。

`make artifact`は`dev`を起動した後、`docker compose exec -T dev /usr/local/bin/poppy-build`を実行します。Docker内でLinux用のコアテストを実行した後、MinGW-w64でWindows x64向けReleaseビルドを行い、`out/docker/Poppy.exe`に出力します。ビルド終了後もコンテナは起動したままです。C++とwinpthreadsのランタイムは静的リンクします。生成した実行ファイルをWindows上で起動してください。

```powershell
.\out\docker\Poppy.exe "C:\work\project"
```

初回のイメージ作成にはDocker HubとDebianパッケージ配布元への接続が必要です。イメージ作成後のテスト・コンパイルは、外部接続できない内部ネットワーク（`internal: true`）で実行します。ソースを読み取り専用でマウントし、中間生成物はComposeの`build-cache`ボリューム、完成した実行ファイルはホストの`out/docker`に保存します。並列コンパイル数は既定で2、`POPPY_BUILD_JOBS`環境変数で変更できます。

`docker/build.sh`はイメージ作成時に`/usr/local/bin/poppy-build`へコピーし、実行権限`0555`で固定します。コンテナのルートファイルシステムも読み取り専用にし、実行中のスクリプト差し替えを防ぎます。ビルドには書き込み可能な`/build`・`/output`と、一時ファイル用の`/tmp`（tmpfs）を使います。リポジトリ側の`docker/build.sh`を編集しても、ホストで`make dev`を実行してイメージを再ビルドするまで、許可済みの実行内容は変わりません。

コンテナを停止する場合は`docker compose stop dev`、削除する場合は`docker compose down`を実行します。中間生成物のキャッシュも破棄して作り直す場合は、`docker compose down --volumes`を実行します。旧`build`サービスから移行する場合は、`docker compose down --remove-orphans --volumes`で旧コンテナと旧マウント先を記録したCMakeキャッシュを削除してから、`make dev`を実行してください。

コンテナ内で実行するテストはLinux版のコアテストです。Windows実行ファイルの起動、GUI、ConPTYの動作確認はWindows実機で行います。

### AIコンテナからビルド・コンパイルチェック

ホスト側のWSL / Linuxでリポジトリのルートから`make dev`を実行し、`.aicontainer`に次の設定を追加します。

```ini
docker-proxy-name=poppy-docker-proxy
docker-proxy-containers=poppy-dev
docker-proxy-allow=sh /usr/local/bin/poppy-build
docker-proxy-allow=cmake
docker-proxy-allow=ctest
docker-proxy-allow=ninja
docker-proxy-allow=g++
docker-proxy-allow=x86_64-w64-mingw32-g++-posix
```

既存の`docker-proxy-allow=sh docker/build.sh`や`docker-proxy-allow=/usr/local/bin/poppy-build`は、上記の`sh`と固定パスを指定する設定に置き換えてください。設定を反映するため、AIコンテナを作り直して起動します。`.aicontainer`はローカル設定としてGit管理から除外されています。

AIコンテナ内でもリポジトリのルートから実行します。

```sh
# コアテストからWindows実行ファイルの生成まで実行
dp sh /usr/local/bin/poppy-build

# 初回ビルド後、Windows向けの差分コンパイルだけを実行
dp cmake --build /build/windows --parallel 2

# Linux用コアの差分コンパイルとテスト
dp cmake --build /build/linux --parallel 2
dp ctest --test-dir /build/linux --output-on-failure
```

Composeはホストの`PWD`と同じ絶対パスにソースをマウントします。`dp`はAIコンテナの作業ディレクトリをそのまま引き継ぐため、`dev`とAIコンテナでリポジトリの絶対パスを揃えてください。

### Windowsで直接ビルド

Visual Studio 2022の「C++によるデスクトップ開発」、Windows SDK、CMakeを用意し、Developer PowerShellで実行します。

```powershell
cmake -S . -B out -A x64 -DBUILD_TESTING=ON
cmake --build out --config Release
ctest --test-dir out -C Release --output-on-failure
.\out\Release\Poppy.exe "C:\work\project"
```

フォルダー指定を省略すると開いていたプロジェクト一覧と選択を復元します。初回起動時は空のウィンドウが開きます。コマンドラインでフォルダーを指定した場合は、そのプロジェクトを優先します。Release版はCRTとSQLiteを静的リンクし、通常のコード表示とシェルには`Poppy.exe`を使います。ai-containerの起動アダプターを使う場合は、同じ場所の`ai/`フォルダーも配布します。通常利用にVisual StudioやCMakeは必要ありません。

### コアテストだけを直接実行

Windows以外でも、ポータブルなテキスト処理・ターミナルモデル・ツリーモデルのテストをネイティブビルドできます。

```sh
cmake -S . -B out -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build out
ctest --test-dir out --output-on-failure
```

## 複数プロジェクトとAI状態

「Open folder」「＋ Open folder」「Ctrl+O」は、現在のプロジェクトを残して追加します。左端の一覧をクリックして切り替えます。一覧の境界はドラッグで調整でき、右クリックまたは中クリックで対象プロジェクトを閉じます。フォルダーやworktree自体は削除しません。同名フォルダーには識別できる親パスを補助表示します。

PROJECTSの行は左ドラッグで並び替えられます。挿入位置の線を目印にマウスを離してください。一覧の上下端に重ねると自動スクロールし、隠れている位置へも移動できます。Esc、キャプチャ喪失、一覧の外でのドロップはキャンセルします。順序は再起動後も復元します。

閉じたプロジェクトも履歴に残り、Ctrl+Rまたは「Open folder」の「Recent projects…」から再び開けます。名前・パスで絞り込み、↑↓とEnter、または行のクリックで選択します。Escや外側のクリックで閉じます。同名フォルダーにはフルパス、WSLにはディストリビューションとユーザーも表示します。既に開いているプロジェクトはそのまま選択し、閉じたものは保存済みのタブや配置を復元します。すべてのプロジェクトを閉じて終了しても、履歴は次回起動時に残ります。

「Open WSL folder…」では、エクスプローラーと同じWindows標準のフォルダー選択で`\\wsl.localhost`配下を辿り、WSLのプロジェクトを開けます。アドレスバーへのパスの貼り付けと、接続ユーザーの指定もできます。ファイル表示・編集・保存・名前変更・検索・Git・ターミナルに対応し、Windowsのプロジェクトと同時に利用できます。配布時は`wsl/poppy-wsl-helper`をPoppy.exeの隣に置いてください。接続・保存の制約と検証範囲は [WSL対応](docs/wsl-support.md) を参照してください。

ターミナル領域の「＋」でシェルを追加し、タブで切り替えます。ターミナルタブの右クリックで名前変更・終了、「＋」の右クリックでCodex・Claude Codeをai-containerで起動できます。設定手順は [ai-container連携](integration/ai/README.md)、所有関係と検証範囲は [実装メモ](docs/multi-project.md) を参照してください。再起動後は構成だけを復元し、以前のAIコマンドを自動実行しません。

プロジェクトとターミナルの状態は、実行中・応答待ち・中断・完了を図形とツールチップで示します。未確認通知は状態とは別に保持し、対象端末を表示したときに消します。完了状態自体は残ります。プロジェクト名は最後の端末へ戻り、状態アイコンは代表状態の端末を開きます。CodexとClaude Codeの既存hook送信形式を受け付け、通常のシェルの生存や無出力時間からAI状態を推測しません。

親フォルダーの下に複数のGitリポジトリがある場合も、その親フォルダーを開けます。たとえば `app/app-client/.git` と `app/app-server/.git` がある構成では `app` を開くと、SOURCE CONTROLとBRANCHにそれぞれのリポジトリを表示します。リポジトリの見出しには親フォルダーからの相対パスと現在のブランチを表示します。Windows・WSLの両方に対応します。

変更一覧のStaged Changes／Changes、ステージ・解除、All Changes、ブランチとコミット履歴、コミットの差分はリポジトリごとに扱います。同じファイル名やブランチ名でも操作先を分け、アイコンの変更数は全リポジトリの合計です。エクスプローラーからのF6も、そのファイルが属する最も内側のリポジトリを使います。`.git`がファイルになっているworktreeやサブモジュールも検出します。

リポジトリの検出は開いたフォルダー自身と子フォルダーを対象にし、開いたフォルダーより上位のリポジトリは含めません。子フォルダーを再帰走査し、`.git`の内部とディレクトリへのリンク／ジャンクションには入りません。最大5万ディレクトリ・20万エントリーを調べ、最大256リポジトリを表示します。変更ファイルの表示は全体で最大5万件です。検出・表示上限に達した場合はステータスに表示します。追加・削除はフォルダーの更新通知とF5で再検出します。

SOURCE CONTROLのアイコンには、変更ファイルと未追跡ファイルの合計をバッジ表示します。ステージ済み・未ステージの両方にあるファイルは1件と数え、変更が0件ならバッジを隠します。ファイルの保存・追加・削除・名前変更をファイルシステムの通知で検知し、一覧と件数を自動更新します。連続する変更は約500 ms待ってまとめ、変更が続く場合も約2秒ごとに更新します。SOURCE CONTROLを開いたときにもGitの状態を再取得します。Git hookの設定は不要です。

ターミナル内では、普段使う`codex`や`claude`などのコマンドを直接実行します。プロバイダーのAPIキーをアプリ側で管理する機能はありません。PowerShellは`-NoProfile`で起動します。

Ctrl+Pのファイル検索は作業フォルダーの配下を対象に、ファイル名を優先して部分一致・あいまい一致で候補を表示します。未展開のフォルダーや未追跡ファイルも検索でき、同名のファイルは相対パスで見分けられます。起動時と作業フォルダーの切り替え時に、`.git`とリンク・ジャンクションを除く全ファイルの相対パスをバックグラウンドで取得します。入力時は取得済みの一覧だけを絞り込み、ディスク走査や入力後の待ち時間を挟みません。表示候補は上位100件までですが、一覧の取得件数に上限はありません。ファイルの追加・削除・名前変更を検知したときとF5で一覧を再取得し、更新中も前回の一覧で検索できます。

Ctrl+Fは未保存の編集を含む、開いている本文を直接検索します。Windows・WSLで同じ処理を使い、追加のファイル読み込みや通信は行いません。通常表示・読み取り専用表示と、差分の画面に表示される本文に対応します。文字列の部分一致で検索し、正規表現・単語境界・複数行の検索には対応していません。大文字小文字を区別しない設定で変換するのはASCII英字だけです。検索語はUTF-16で512コード単位までです。全一致位置を保存せず、件数と移動先を短い処理単位で計算します。描画では表示行の一致だけを再計算します。

Ctrl+Shift+Fは、選択中のプロジェクトの本文を既定で2並列・64 KiBずつ読み込んで検索します。WSLではLinuxヘルパー内で走査・検索し、一致した相対パス・行・列・抜粋だけをWindowsへ返します。未保存のファイルはエディター内の本文をコピーせずに検索し、保存済みの同じファイルとの重複を防ぎます。入力変更から150 ms後に検索を開始し、結果は順次表示します。入力変更・プロジェクトやサイドバーの切り替え・Escで古い検索をキャンセルします。結果を開く時点で一致文字列を確認し、変わっていれば再検索を案内します。

既定では`.gitignore`・`.ignore`と通常の`.git/info/exclude`の規則を使います。隠しファイルも対象ですが、`.git`・`.hg`・`.svn`とリンク・ジャンクションは常に除きます。不正な文字コード・バイナリ、16 MiB超、100万行超のファイルは対象外です。結果は最大2,000件・構造体と文字列の概算2 MiB、抜粋は512バイト以内です。件数・容量の上限や読み込みエラーは検索欄の下に表示します。SQLiteへの本文保存や全文索引の構築は行いません。対応する除外規則、通信・メモリの上限、計測方法は[検索の実装と設計](docs/search.md)を参照してください。

アクティビティーバーのアイコンでサイドバーを切り替えます。選択中のアイコンには左端に目印が付き、アイコンにマウスを重ねると名前とショートカットを表示します。エクスプローラーの展開状態は切り替えても保持します。

ツリーは矢印のクリックやフォルダー名のダブルクリックで展開・折りたたみできます。キーボードでは上下矢印で選択、右矢印で展開または子へ移動、左矢印で折りたたみまたは親へ移動します。Home / End / Page Up / Page Down、名前の先頭文字による検索、縦横スクロールにも対応します。フォルダーの読み込み中も折りたたみを受け付けます。アクティビティーボタンはクリック、Enter、Spaceで切り替えられ、Spaceはキーを離したときに確定します。

ファイルは複数のタブで開けます。タブの幅はファイル名の長さに合わせて変わります。タブはビューアーの幅に合わせて複数段に折り返し、ファイルを閉じたり幅を広げたりすると段数が減ります。高さに収まらない場合はコード表示領域を確保し、タブ領域の右下の`‹` / `›`で段単位に送れます。各タブのスクロール位置・選択範囲・通常表示／差分表示の状態を保持し、タブにマウスを重ねるとフルパスを表示します。通常表示と差分表示はそれぞれの表示位置を保持します。切り替え時にファイルや差分を読み直すため、非表示中の外部変更も反映します。別のフォルダーはプロジェクト一覧へ追加します。登録済みのフォルダーは同じプロジェクトを選び、ツリー・タブ・本文・入力先をメモリから表示します。切り替え時にSQLiteやGitの完了を待ちません。

Gitはブランチ、変更数、未追跡ファイル数を表示します。SOURCE CONTROLは`Staged Changes`と`Changes`を分けて表示し、部分的にステージしたファイルは両方に表示します。前者はHEADとインデックス、後者はインデックスと作業ツリーの差分を開きます。各グループの右側の差分アイコン（`Open All Changes`）で、そのグループの差分を1つのタブにまとめて表示します。Changesの差分一覧には未追跡ファイルも追加ファイルとして含めます。単独の未追跡ファイルは通常のファイル表示を使います。

SOURCE CONTROLのファイル行にマウスを重ねると、`Changes`には＋アイコン（`Stage Changes`）、`Staged Changes`には−アイコン（`Unstage Changes`）を表示します。クリックするとファイル単位でステージ／解除し、一覧・変更件数・表示中の差分を更新します。未追跡ファイル、削除、リネームにも対応し、作業ツリーの内容は保持します。グループの差分アイコンもマウスを重ねたときに表示します。

`Changes`の見出しにマウスを重ねると、差分アイコンの左に＋アイコン（`Stage All Changes`）を表示します。クリックすると、そのリポジトリ全体の変更・削除・リネーム・未追跡ファイルをまとめてステージし、一覧・変更件数・表示中の差分を更新します。部分ステージしたファイルも作業ツリーの最新内容をステージします。無視されたファイルは追加しません。複数リポジトリではクリックした見出しのリポジトリだけを対象にし、変更がないグループにはボタンを表示しません。見出しを折りたたんでいても使えます。Windows・接続済みWSLの両方に対応します。

`Staged Changes`の見出しにマウスを重ねると、差分アイコンの左に−アイコン（`Unstage All Changes`）を表示します。クリックすると、そのリポジトリ全体のステージを解除し、一覧・変更件数・表示中の差分を更新します。作業ツリーの内容とHEADは保持し、追加ファイルは未追跡に、削除・リネームは未ステージの変更に戻ります。部分ステージや初回コミット前にも対応します。複数リポジトリではクリックした見出しのリポジトリだけを対象にし、ステージ済みの変更がないグループにはボタンを表示しません。見出しを折りたたんでいても使えます。Windows・接続済みWSLの両方に対応します。

`Changes`の見出しにマウスを重ねると、＋アイコンの左に戻す矢印（`Discard All Changes`）を表示します。確認ダイアログでOKを選ぶと、そのリポジトリの未ステージ変更をインデックスの内容へ戻し、無視されていない未追跡ファイル・フォルダーを完全に削除します。元に戻せないため、確認の初期選択はCancelです。部分ステージのステージ済み内容、HEAD、無視ファイル、未追跡の入れ子リポジトリ、サブモジュール、エディターの未保存本文は保持します。競合がある場合は何も変更せず停止します。見出しを折りたたんでいても利用でき、一覧・変更件数・表示中のファイルと差分を更新します。Windows・接続済みWSLの両方に対応し、初回コミット前も使えます。復元後もサブモジュール内部の変更はChangesに残ります。処理途中にエラーが発生した場合は停止して一覧を更新し、完了済みの復元・削除は取り消しません。

`Changes`の見出しにマウスを重ねると、Discardの左に退避アイコン（`Stash Unstaged Changes`）を表示します。クリックすると、そのリポジトリの未ステージ変更と無視されていない未追跡ファイルをGitのStashへ保存し、作業ツリーをインデックスの内容へ戻します。部分ステージを含むステージ済み内容、HEAD、無視ファイル、エディターの未保存本文は保持します。見出しを折りたたんでいても使え、一覧・変更件数・表示中のファイルと差分を更新します。複数リポジトリではクリックした見出しのリポジトリだけを対象にし、Windows・接続済みWSLの両方に対応します。

Gitの`stash push --keep-index --include-untracked`を使うため、Stashには作業ツリーに加えてステージ済み内容のスナップショットも保存されます。名前は`Poppy: unstaged changes`で、ターミナルの`git stash list`等から確認・復元できます。競合がある場合と初回コミット前は退避せずエラーを表示します。ステージした新規ファイルを作業ツリーで削除した状態も、Gitがその削除を退避しないため停止します。先に該当ファイルのステージを解除してください。保存・作成・名前変更などが処理中の場合は完了後に実行してください。失敗時も一覧を更新し、Gitのエラーを表示します。サブモジュール内部の変更は退避しません。

`Staged Changes`の見出しにマウスを重ねると、−アイコンの左に退避アイコン（`Stash Staged Changes`）を表示します。クリックすると、そのリポジトリのステージ済み変更だけをGitのStash（`Poppy: staged changes`）へ保存し、インデックスと作業ツリーから取り除きます。未ステージ変更、未追跡・無視ファイル、HEAD、エディターの未保存本文を保持します。追加・削除・リネーム・バイナリに対応し、折りたたんだ見出しからも利用できます。複数リポジトリではクリックした見出しのリポジトリだけを対象にし、一覧・変更件数・表示中のファイルと差分を更新します。Windows・接続済みWSLの両方に対応します。

Git 2.35以降の`stash push --staged`を使います。部分ステージは変更箇所が離れていれば退避でき、ステージ済みと未ステージの変更が重なるなど、Gitが作業ツリーから取り除けない場合はエラーを表示します。この場合、Stashが作成済みのことがあるため、再実行前に`git stash list`と作業ツリー・インデックスを確認してください。競合は処理前に拒否し、初回コミット前や未対応のGitではエラーを表示します。失敗時も一覧を更新します。サブモジュール内部の変更は退避せず、保存・作成・名前変更などとの同時実行も行いません。

Git一覧は初期状態では`Tree`表示です。`Tree` / `List`で変更ファイルの表示を切り替えられます。相対パスはGitリポジトリのルートを基準に表示します。Treeのフォルダーは矢印やダブルクリック、左右矢印・Enter・Spaceで展開・折りたたみでき、更新や表示の切り替えでも折りたたみ状態を保持します。表示形式はプロジェクトごとに保存し、再起動後も復元します。エクスプローラーとGit一覧の状態は名前の色で示します。追加・未追跡は緑、削除・競合は赤、変更・リネームなどは黄です。選択中も状態の色を保持します。削除済みファイルも差分を開けます。コミット操作はターミナルで行います。

アクティビティーバーの`Branch`またはCtrl+Shift+Bで`BRANCH`ページを開きます。ローカル・リモート追跡ブランチをツリーで表示し、ブランチを開くと新しい順に50件のコミットを表示します。51件目の行の`Load 50 more commits…`をクリックすると、さらに50件ずつ追加します。コミットを開くと変更ファイルをフォルダーのツリーで表示し、ファイルを選ぶとそのコミット時点の差分を開きます。コミット行にマウスを重ねると右側に差分アイコンが現れ、クリックすると全変更を1つの差分タブに表示します。アイコンのツールチップは`Open All Changes`です。初回コミットは追加ファイルとして、マージコミットは最初の親との差分として表示します。現在のブランチを切り替えずに履歴を閲覧でき、detached HEADも表示します。コミットとSOURCE CONTROLのグループを選んでF4を押しても`Open All Changes`を実行できます。

差分は初期状態では`Inline`表示です。見出しの`Split` / `Inline`またはF7で左右比較とインライン表示を切り替えられます。左右比較では変更前を左、変更後を右に並べ、各ファイルの行番号を表示します。インラインでは削除行、追加行を順に1列へ並べ、変更前・変更後の行番号を2列で表示します。共通行は1回だけ表示します。削除行は薄い赤、追加行は薄い緑の背景で示し、本文は通常のファイル表示と同じシンタックスハイライトを使います。左右比較のスクロールは同期します。差分一覧ではファイル名の見出しとバイナリー・空ファイル・属性変更の案内を表示します。`@@`や行頭の差分記号は表示しません。選択・コピーは左右比較では選んだ側、インラインでは表示された削除・追加行を含む本文が対象です。表示形式はプロジェクト単位で保存し、同じプロジェクト内のすべての差分タブに共通で適用します。ファイルの切り替えや再起動後も選んだ形式を使い、形式の切り替え時には表示中の行をできるだけ維持します。表示するのは変更箇所とその前後の行で、離れた変更箇所では行番号が飛びます。比較対象（作業ツリー・ステージ済み・コミット）とコミットIDをタブごとに保存し、再起動後も同じ比較を復元します。

差分のハイライトは作業ツリー・ステージ済み・コミットと`Open All Changes`に共通で適用します。ファイルごとに変更前・変更後のパスから言語を選び、同じ変更範囲内の複数行コメント・文字列は左右それぞれの状態を保持します。省略された本文で始まるコメント・文字列の状態は復元せず、変更範囲（ハンク）の先頭から解析します。未対応の拡張子は通常色で表示します。

AIなどによるフォルダー内の変更を検知し、500 msの待ち合わせ後に再取得します。変更が続く場合は約2秒ごとに更新を依頼します。OS通知が利用できない場合や作業フォルダー外での変更は、F5で更新できます。読み込み中の新しい結果が届くまで時間がかかる場合があります。

各プロジェクトが専用の複数ターミナルを持ちます。非表示でもConPTYの受信・VT解析・応答を続け、再選択時に同じプロセスと画面を表示します。通常のシェルは所属プロジェクトのフォルダーで起動します。ターミナルを閉じると対象のプロセスと子プロセスを終了します。ai-containerの停止にはホスト側アダプターの終了要求を使い、確認できない場合は終了未確認と表示します。

## 作業領域と前回状態の復元

保存先は `%APPDATA%\yumayo\Poppy` です。`APPDATA` が未設定の環境ではWindowsのRoaming AppDataフォルダーを使います。

```text
%APPDATA%\yumayo\Poppy\
  storage.sql
  projects\
    -d-repository-yumayo-poppyworktrees-poppydirect2d\
      storage.sql
```

全体の `storage.sql` はSQLite3のデータベースで、前回のプロジェクト、ウィンドウの位置・大きさ・最大化状態、プロジェクトと保存先の対応を管理します。プロジェクトごとの `storage.sql` には共通の差分表示形式（Split／Inline）、タブの順序と選択、各タブの表示位置・選択範囲・通常／差分表示、エクスプローラーの展開と選択、サイドバーの種類と幅、ターミナルの表示と高さを保存します。開いている一覧と選択・一覧幅、各ペインの選択とスクロール、Gitの折りたたみ、ターミナルID・名前・順序・起動フォルダーも保存します。操作後650 msの待ち合わせを経て、専用ワーカーがSQLite接続を所有して保存します。プロジェクトの切り替えは保存を待ちません。終了時は非表示プロジェクトも保存します。

プロジェクトの保存先名は絶対パスを小文字にして区切り文字などをハイフンへ置き換えます。同じ名前になる別のパスにはハッシュの接尾辞を付け、既存の保存先と分けます。長い名前は短縮してハッシュを付けます。再起動時は通常表示のファイルが削除されていればそのタブを除外し、削除ファイルの差分タブは復元します。ターミナルの実行プロセスや出力履歴は復元せず、次に操作したときに新しいPowerShellを起動します。

保存はトランザクションで行い、プロジェクトの保存中に失敗した場合は前回の状態を残します。読み込み・保存に失敗した場合はメッセージを表示します。より新しいバージョンの保存形式は上書きしません。

保存先の命名規則、SQLiteのテーブルとカラム、保存・復元の流れは [DATASTRUCTURE.md](DATASTRUCTURE.md) にまとめています。

## メモリを抑える構成

- ファイルツリーは`.git`を含めて展開した階層だけ列挙し、折りたたんだ配下のノードを解放します。ディレクトリのリンク・ジャンクションは再帰展開しません。
- 各プロジェクトで最後に表示した本文を保持し、全体64 MiBを超えた場合は古い非表示プロジェクトの本文から解放します。解放後はタブと位置を先に表示し、本文を非同期で読み直します。各プロジェクト内では表示中のファイル本文だけを保持します。非表示タブにはファイルパス・表示位置・選択範囲・差分表示の状態だけを残し、切り替え時に本文を読み直します。本文のUTF-8スナップショットと行頭位置・行ごとの字句状態を保持し、表示行のトークンと描画用文字列をその場で作ります。Ctrl+P用に全ファイルの相対パスと検索用の正規化済みパスを保持しますが、非表示ファイルの本文や全行の描画キャッシュは保持しません。
- ディスクI/OとGitは別のワーカーで処理し、UIスレッドでファイル走査やGitの終了待ちを行いません。古い読み込み結果を表示しないよう世代と要求番号を確認します。
- シェルは操作時に起動します。ターミナルは固定セルの画面と上限付き履歴を持ち、外部ターミナルアプリを埋め込む構成にはしません。
- 大量のターミナル出力は8 KiB単位で全セッションを順番に処理し、時間が残っていれば同じ回で続きを解析します。全体の解析時間を約16 msあたり5 ms以内に制限し、続きを共有タイマーで処理します。表示が追いつかない場合は出力側を待機させ、メモリ増加とUIの占有を抑えます。
- ターミナルの表示は確定した可視画面を保持し、連続する出力は32 msの待ち合わせでまとめます。キー入力後250 msの間は、受信待ちが空になれば最初の出力から16 msを目安に画面を更新し、長押し中も待ち時間を延長しません。リサイズ後は100 ms待ち、出力やリサイズが続く場合も120 msごとに表示を更新します。手動スクロールは出力の待ち合わせを挟まず、その場で表示と描画を更新します。同期更新の指定中は終了指定まで画面を保持し、終了指定が欠けた場合は1秒で解除します。同期更新中に要求したスクロール位置は画面の確定時に反映します。再表示・フォーカス変更やコピーにも表示用の画面を使い、表示更新を待っている間の途中経過が現れないようにします。
- ディレクトリー変更の完了イベントは80 msの共有タイマーで確認し、プロジェクト数をUIの待機ハンドル数に直結させません。Gitの常時取得は行わず、変更通知、選択時、再アクティブ時、F5で再検証します。

| 項目 | 初期上限 |
| --- | --- |
| ファイル | 読み込み時・UTF-8変換後ともに16 MiB / 1,000,000行 |
| 長い行の表示 | 先頭8,192桁まで。コピー対象には全文が残る |
| ファイルツリー | 1フォルダー10,000件 / 全体50,000ノード |
| Git変更ファイル一覧 / 状態の色分け | 50,000ファイル / 親ディレクトリを含め50,000パス |
| GitのTree表示の親フォルダー | 最大50,000ノード。上限を超える階層は残りの相対パスをファイル名として表示する |
| Gitコマンドの出力 | 1回4 MiB / 差分は1,000,000行まで |
| ターミナル画面 | 最大500列 × 200行 × 通常・代替の2画面 |
| ターミナル表示用画面 | 最大500列 × 200行の1画面。履歴は複製しない |
| ターミナル履歴 | 最大1,000行、かつ131,072セル。セル領域は約2 MiB以内 |
| ターミナル受信待ち | 256 KiB。超過時はパイプ読み取りを待機する |
| ターミナル送信待ち | 1 MiB。超過する入力は受け付けない |

これらはアプリ全体のメモリ上限ではありません。読み込み中の旧・新ファイル、UTF-16変換、コピー、Gitの結果入れ替えなどで一時的な追加領域を使用します。Windowsの共有DLL、ツリーの階層・表示位置とラベル幅のキャッシュ、Direct2Dの描画先やGPUドライバーの領域も必要です。PowerShell・AI CLI・Gitは別プロセスでメモリを使います。

## 初版の表示範囲

ファイル表示はUTF-8、BOM付きUTF-16 LE / BEに対応します。バイナリーやShift_JISなどはプレビュー対象外です。簡易シンタックスハイライトはC/C++、C#、JavaScript/TypeScript、Rust、Go、JavaなどのC系構文、Python、シェル、JSON、TOML/YAML/INI、Git差分を対象とします。言語の完全な構文解析は行いません。

ターミナルはConPTYのUTF-8出力を受け取り、基本的なカーソル移動、行・文字の挿入と削除、スクロール領域、代替画面、16/256/true color、bracketed paste、カーソル・背景色の照会、同期更新（DEC private mode 2026）の開始・終了と状態照会に対応する小さなVT実装です。日本語などの全角文字とIMEの確定文字列を扱うコードを含みます。

Windows Terminal相当の互換性はまだありません。結合文字・ZWJ絵文字の合成、文字装飾の完全再現、マウスプロトコル、画像、Kittyキーボードプロトコル、履歴の折り返し再計算は未対応です。使うAI CLIで表示と操作を確認する必要があります。

## Editorでの修正

通常の本文表示は、Editorの表示幅に合わせて長い行を折り返します。読み取り専用表示でも同じ動作です。折り返しによってファイルへ改行を追加することはありません。リサイズ・左右分割・DPI変更時に表示幅を再計算し、カーソル移動・選択・検索も折り返した表示行に対応します。行番号は元の行の先頭だけに表示します。折り返し行の途中の表示位置も、タブ切り替え・再起動時に復元します。

Git差分のInline／Split表示も同じフラグで折り返します。Splitでは各ペインの幅で折り返し、左右のうち長い側に高さを合わせて次の行の位置をそろえます。選択・コピー・検索に対応し、Inline／Splitの切り替えやリサイズ後も元の本文位置を基準に表示位置を復元します。

将来の設定画面から切り替えられるよう、`Viewer::setWordWrap(bool)`と`Viewer::wordWrap()`を用意しています。既定値は`true`で、`false`にすると横スクロールへ戻ります。設定画面・設定の保存はまだ追加していません。

通常のファイル表示で文字入力、日本語IME、選択置換、Enter、Tab、Backspace / Delete、矢印・Home / End・Page Up / Down（Shiftで選択、Ctrl+Home / Endで先頭・末尾）が使えます。Ctrl+C / X / V、Ctrl+A、Ctrl+Z（Undo）、Ctrl+Y / Ctrl+Shift+Z（Redo）、Ctrl+S（保存）と右クリックメニューに対応します。Git差分は読み取り専用です。

未保存タブには `*` と `Modified` を表示します。タブ・プロジェクト切り替え、F5、AIによるファイル更新でも未保存本文を保持し、タブ・プロジェクト・アプリを閉じるときは保存・破棄・キャンセルを選択できます。未保存本文はメモリ内だけで保持し、異常終了からの復元は行いません。保存はUTF-8（BOM有無）、BOM付きUTF-16 LE / BEと既存改行を維持し、新規改行・貼り付けは最初の改行形式に合わせます。外部更新後の保存は拒否して編集を保持するため、必要な修正をコピーしてタブを閉じ、最新ファイルを開いて反映してください。一時ファイルを書き終えてから元ファイルを置換します。

ファイルは16 MiB・100万行未満、Undoは直近1,000操作・約16 MiBを目安に制限します。簡単な修正向けに各操作後に行索引とハイライト状態を更新します。未保存ファイルはメモリ回収の対象外です。

## Editor / Terminalの左右分割

タブを本文の左半分または右半分へドラッグすると、同じ領域に2つのタブグループを左右に並べます。EditorとTerminalはそれぞれ分割でき、各グループでファイル・セッションを切り替えられます。移動先の色付き領域を確認してマウスを離してください。既存グループのタブ見出しへドロップすれば、そのグループへの移動と並び替えができます。Esc、キャプチャ喪失、領域外へのドロップでキャンセルします。

中央の境界をドラッグすると左右の幅を変更します。片側の最後のタブを移動・クローズすると1グループへ戻ります。タブの所属、左右の選択、境界幅をプロジェクト単位で保存し、再起動後も復元します。Terminalの移動はConPTYを再起動しません。各グループの `+` で同じグループにシェルを追加でき、`+` の右クリックメニューからAIを起動できます。

EXPLORERのファイルやフォルダーは、同じプロジェクト内の別のフォルダーへ左ドラッグで移動できます。移動先の行が強調表示されたらマウスを離してください。ルートの行や一覧下の空白へのドロップでプロジェクト直下へ移動します。フォルダーに600 ms重ねると展開し、一覧の上下端では自動スクロールします。Esc、キャプチャ喪失、領域外へのドロップでキャンセルします。プロジェクトのルート自身、自分自身や配下、現在の親、リンク／ジャンクションのフォルダーへの移動はできません。同名の項目がある場合は上書きせずエラーを表示します。Windows・接続済みWSLの両方で利用でき、開いたタブ・未保存本文の保存先・ツリーの展開状態も追従します。

移動は`tests/tree_tests.cpp`で階層・兄弟順・展開と選択の保持、循環や不正な移動の拒否を、`tests/wsl_helper_tests.cpp`で実ファイル・フォルダーの移動、日本語・空白・バックスラッシュを含む名前、同名衝突・古い版・不正な移動先・リンクの拒否と移動後の保存を検証します。`tests/folder_tests.cpp`にはクリックとドラッグの区別、キャンセル・無効な移動、タブと未保存本文の保持、移動先への保存、衝突時のエラー、再起動後の復元を確認するWindows用GUIテストがあります。GUI操作の実行検証にはWindowsのデスクトップ環境が必要です。

Ctrl+NでEXPLORERに切り替え、新しいファイルのパスを入力できます。選択したフォルダー内、ファイル選択時はその親、選択がなければプロジェクトのルートが作成先です。エディター・ツリー・ターミナルから使えます。EXPLORERのフォルダー（プロジェクトのルートを含む）の右クリック → `New File…` / `New Folder…`からも作成できます。

フォルダーの行に表示される入力欄でEnterを押すと作成し、Escや入力欄の外へのフォーカス移動でキャンセルします。`path/to/file.md`は不足する中間フォルダーも作成します。末尾が `/` の `path/to/folder/` はフォルダーを作成します。区切りはWindows・WSLとも `/` を使い、絶対パス、`.`、`..`、空のパス要素は受け付けません。入力は最大4,096文字、各要素はWindowsでは255文字、WSLでは255 UTF-8バイトまでです。既存の中間フォルダーは利用し、最後の同名ファイルやフォルダーは上書きしません。作成後は親フォルダーを展開して新しい項目を選択し、ファイルはエディターで開きます。Windows・接続済みWSLの両方で利用できます。リンク／ジャンクションを中間フォルダーとして使うことはできません。作成が途中で失敗した場合、それまでに作成した中間フォルダーは残ります。

クリップボードに画像があるとき、EXPLORERでCtrl+V、または右クリック → `Paste Image`でPNGを新規作成します。選択したフォルダー内、ファイル選択時はその親、空白部分の右クリックではプロジェクトのルートに保存します。名前はローカル時刻の `paste-yyyy-MM-ddThh-ii-ss.png`（24時間表記、`ii`は分）です。同じ秒の同名ファイルがあれば上書きせずエラーを表示します。作成後はフォルダーを展開し、新しい画像を選択します。画像のプレビューはまだありません。

Windows・接続済みWSLの両方で利用できます。PNG形式とWindowsのDIB／DIBV5形式（スクリーンショット等）に対応し、クリップボードと展開後の画素は64 MiB、PNGファイルは16 MiBまでです。画像の変換と保存はバックグラウンドで行います。テキストの貼り付けや、ファイルそのもののコピー＆貼り付けはEXPLORERでは扱いません。

EXPLORERのファイル／フォルダー（プロジェクトのルートを含む）やファイルのタブを右クリック → `Reveal in File Explorer`で、WindowsのFile Explorer（explorer.exe）に対象を選択して表示します。空白や日本語を含むパスにも対応します。WSLは`\\wsl.localhost`経由で表示し、Windows側のWSL共有のアクセス権を使います。名前にバックスラッシュを含むWSLパスは表示できません。コミット時点のファイルや`All Changes`のタブには、この項目を表示しません。表示に失敗するとエラーを表示します。

エクスプローラーのファイルやエディターのタブを右クリック → `Open with Default Application`で、Windowsに関連付けられたアプリケーションで開きます。ディスク上のファイルを開くため、Poppyでの未保存の編集は先にCtrl+Sで保存してください。起動に失敗するとWindowsのエラーを表示します。

ファイルやフォルダーを選んでF2、または右クリック → Renameを選びます。名前を入力してEnterで確定、Escや入力欄の外へのフォーカス移動でキャンセルします。ファイルは拡張子を除く部分を最初に選択します。プロジェクトのルートフォルダーは変更できません。既存の同名ファイルへの上書きは行いません。

成功すると開いているタブ、未保存本文の保存先、フォルダー配下のパス、ツリーの展開・選択、ファイル検索とGit一覧を更新します。Terminalの次回起動ディレクトリも追従します。実行中のシェルのカレントディレクトリは変更しません。権限不足や使用中のフォルダーなどの失敗はWindowsのエラーを表示します。
