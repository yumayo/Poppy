# Poppy

Windows専用の、AI CLIと一緒に使う小さなコードエディターです。左端にプロジェクト一覧、その右にアイコンだけのアクティビティーバーとエクスプローラー／Gitのサイドバー、さらに右に編集可能なコード表示、右下にターミナルを配置します。AIに編集を任せながら、人間による小さな修正も行えます。

C++17 / Win32 / Direct2D / DirectWrite / ConPTYで実装し、ブラウザー、WebView、Node.js、.NETランタイム、エディターエンジンを常駐させません。LSP、拡張機能は入れていません。

コードビューアー、ターミナル、ツールバー、タブ、ファイルツリー、Git一覧、アクティビティーボタン、スクロールバーをDirect2Dで描画し、文字の整形とフォントのフォールバックはDirectWriteを使います。ツリーとボタンも独自のウィンドウで描画し、アプリからGDIの描画・フォントAPIを呼び出したり、`gdi32`へ直接リンクしたりする処理はありません。描画テストのビットマップにはWICを使います。スクロールバーはアプリの暗いテーマに合わせ、通常・ホバー・ドラッグ中の色を切り替えます。メニュー、ツールチップはWindowsが描画する標準UIを使います。

コードとターミナルは全角文字を含めて固定セルの位置に描画します。ウィンドウの描画先はハードウェア描画を優先し、作成できない場合はDirect2Dのソフトウェア描画を使います。リサイズとモニターごとのDPI変更に対応し、描画リソースの喪失時は描画先を再作成します。Direct2D、DirectWrite、WICはWindowsに含まれるため、配布用の追加ランタイムは不要です。

**初期実装です。Windows上での動作、実際のAI CLIとの互換性、メモリ使用量は未検証です。** Docker上でのWindows向けクロスビルドとLinux用コアテストは実行済みです。メモリ使用量の達成値は記載していません。

## ビルド

生成するアプリはWindows 10 version 1809以降のx64環境が対象です。Git表示には、別途Git for WindowsをPATHに追加してください。AI CLIも利用するものを別途インストールします。

状態の保存にはSQLite3を使います。SQLite3はC++標準ライブラリには含まれません。`third_party/` はGit管理対象外のため、ビルド前に [SQLite公式サイト](https://sqlite.org/download.html) の `sqlite-amalgamation-*.zip` から、同じリリースの `sqlite3.c` と `sqlite3.h` を `third_party/sqlite/` に配置してください。SQLite 3.54.1でビルドと保存テストを確認しています。CMakeで静的リンクするため、配布先にSQLiteのDLLを追加する必要はありません。

### Dockerでビルド

GNU Makeを用意し、Docker DesktopをLinuxコンテナモードで起動して、リポジトリのルートで実行します。ホスト側のVisual StudioやCMakeは不要です。

```sh
make dev
make artifact
```

`make dev`は`docker compose up -d --build dev`を実行し、`poppy-dev`コンテナを常駐させます。Dockerの再起動後も自動起動します。明示的に停止した場合は`make dev`で再開できます。

`make artifact`は`dev`を起動した後、`docker compose exec -T dev /usr/local/bin/poppy-build`を実行します。Docker内でLinux用のコアテストを実行した後、MinGW-w64でWindows x64向けReleaseビルドを行い、`out/docker/Poppy.exe`に出力します。ビルド終了後もコンテナは起動したままです。C++とwinpthreadsのランタイムは静的リンクします。生成した実行ファイルをWindows上で起動してください。

```powershell
.\out\docker\Poppy.exe "C:\work\project"
```

初回のイメージ作成にはDocker HubとDebianパッケージ配布元への接続が必要です。イメージ作成後のテスト・コンパイルは、外部接続できない内部ネットワーク（`internal: true`）で実行します。ソースを読み取り専用でマウントし、中間生成物はComposeの`build-cache`ボリューム、完成した実行ファイルはホストの`out/docker`に保存します。並列コンパイル数は既定で2、`POPPY_BUILD_JOBS`環境変数で変更できます。

`docker/build.sh`はイメージ作成時に`/usr/local/bin/poppy-build`へコピーし、実行権限`0555`で固定します。コンテナのルートファイルシステムも読み取り専用にし、実行中のスクリプト差し替えを防ぎます。ビルドには書き込み可能な`/build`・`/output`と、一時ファイル用の`/tmp`（tmpfs）を使います。リポジトリ側の`docker/build.sh`を編集しても、ホストで`make dev`を実行してイメージを再ビルドするまで、許可済みの実行内容は変わりません。

コンテナを停止する場合は`docker compose stop dev`、削除する場合は`docker compose down`を実行します。中間生成物のキャッシュも破棄して作り直す場合は、`docker compose down --volumes`を実行します。旧`build`サービスから移行する場合は、`docker compose down --remove-orphans --volumes`で旧コンテナと旧マウント先を記録したCMakeキャッシュを削除してから、`make dev`を実行してください。

コンテナ内で実行するテストはLinux版のコアテストです。Windows実行ファイルの起動、GUI、ConPTYの動作確認はWindows実機で行います。

### AIコンテナからビルド・コンパイルチェック

ホスト側のWSL / Linuxでリポジトリのルートから`make dev`を実行し、`.aicontainer`に次の設定を追加します。

```ini
docker-proxy-name=poppy-docker-proxy
docker-proxy-containers=poppy-dev
docker-proxy-allow=sh /usr/local/bin/poppy-build
docker-proxy-allow=cmake
docker-proxy-allow=ctest
docker-proxy-allow=ninja
docker-proxy-allow=g++
docker-proxy-allow=x86_64-w64-mingw32-g++-posix
```

既存の`docker-proxy-allow=sh docker/build.sh`や`docker-proxy-allow=/usr/local/bin/poppy-build`は、上記の`sh`と固定パスを指定する設定に置き換えてください。設定を反映するため、AIコンテナを作り直して起動します。`.aicontainer`はローカル設定としてGit管理から除外されています。

AIコンテナ内でもリポジトリのルートから実行します。

```sh
# コアテストからWindows実行ファイルの生成まで実行
dp sh /usr/local/bin/poppy-build

# 初回ビルド後、Windows向けの差分コンパイルだけを実行
dp cmake --build /build/windows --parallel 2

# Linux用コアの差分コンパイルとテスト
dp cmake --build /build/linux --parallel 2
dp ctest --test-dir /build/linux --output-on-failure
```

Composeはホストの`PWD`と同じ絶対パスにソースをマウントします。`dp`はAIコンテナの作業ディレクトリをそのまま引き継ぐため、`dev`とAIコンテナでリポジトリの絶対パスを揃えてください。

### Windowsで直接ビルド

Visual Studio 2022の「C++によるデスクトップ開発」、Windows SDK、CMakeを用意し、Developer PowerShellで実行します。

```powershell
cmake -S . -B out -A x64 -DBUILD_TESTING=ON
cmake --build out --config Release
ctest --test-dir out -C Release --output-on-failure
.\out\Release\Poppy.exe "C:\work\project"
```

フォルダー指定を省略すると開いていたプロジェクト一覧と選択を復元します。初回起動時は空のウィンドウが開きます。コマンドラインでフォルダーを指定した場合は、そのプロジェクトを優先します。Release版はCRTとSQLiteを静的リンクし、通常のコード表示とシェルには`Poppy.exe`を使います。ai-containerの起動アダプターを使う場合は、同じ場所の`ai/`フォルダーも配布します。通常利用にVisual StudioやCMakeは必要ありません。

### コアテストだけを直接実行

Windows以外でも、ポータブルなテキスト処理・ターミナルモデル・ツリーモデルのテストをネイティブビルドできます。

```sh
cmake -S . -B out -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build out
ctest --test-dir out --output-on-failure
```

## 複数プロジェクトとAI状態

「Open folder」「＋ Open folder」「Ctrl+O」は、現在のプロジェクトを残して追加します。左端の一覧をクリックして切り替えます。一覧の境界はドラッグで調整でき、右クリックまたは中クリックで対象プロジェクトを閉じます。フォルダーやworktree自体は削除しません。同名フォルダーには識別できる親パスを補助表示します。

ターミナル領域の「＋」でシェルを追加し、タブで切り替えます。ターミナルタブの右クリックで名前変更・終了、「＋」の右クリックでCodex・Claude Codeをai-containerで起動できます。設定手順は [ai-container連携](integration/ai/README.md)、所有関係と検証範囲は [実装メモ](docs/multi-project.md) を参照してください。再起動後は構成だけを復元し、以前のAIコマンドを自動実行しません。

プロジェクトとターミナルの状態は、実行中・応答待ち・中断・完了を図形とツールチップで示します。未確認通知は状態とは別に保持し、対象端末を表示したときに消します。完了状態自体は残ります。プロジェクト名は最後の端末へ戻り、状態アイコンは代表状態の端末を開きます。CodexとClaude Codeの既存hook送信形式を受け付け、通常のシェルの生存や無出力時間からAI状態を推測しません。

ターミナル内では、普段使う`codex`や`claude`などのコマンドを直接実行します。プロバイダーのAPIキーをアプリ側で管理する機能はありません。PowerShellは`-NoProfile`で起動します。

Ctrl+Pのファイル検索は作業フォルダーの配下を対象に、ファイル名を優先して部分一致・あいまい一致で候補を表示します。未展開のフォルダーや未追跡ファイルも検索でき、同名のファイルは相対パスで見分けられます。起動時と作業フォルダーの切り替え時に、`.git`とリンク・ジャンクションを除く全ファイルの相対パスをバックグラウンドで取得します。入力時は取得済みの一覧だけを絞り込み、ディスク走査や入力後の待ち時間を挟みません。表示候補は上位100件までですが、一覧の取得件数に上限はありません。ファイルの追加・削除・名前変更を検知したときとF5で一覧を再取得し、更新中も前回の一覧で検索できます。

アクティビティーバーのアイコンでサイドバーを切り替えます。選択中のアイコンには左端に目印が付き、アイコンにマウスを重ねると名前とショートカットを表示します。エクスプローラーの展開状態は切り替えても保持します。

ツリーは矢印のクリックやフォルダー名のダブルクリックで展開・折りたたみできます。キーボードでは上下矢印で選択、右矢印で展開または子へ移動、左矢印で折りたたみまたは親へ移動します。Home / End / Page Up / Page Down、名前の先頭文字による検索、縦横スクロールにも対応します。フォルダーの読み込み中も折りたたみを受け付けます。アクティビティーボタンはクリック、Enter、Spaceで切り替えられ、Spaceはキーを離したときに確定します。

ファイルは複数のタブで開けます。タブの幅はファイル名の長さに合わせて変わります。タブはビューアーの幅に合わせて複数段に折り返し、ファイルを閉じたり幅を広げたりすると段数が減ります。高さに収まらない場合はコード表示領域を確保し、タブ領域の右下の`‹` / `›`で段単位に送れます。各タブのスクロール位置・選択範囲・通常表示／差分表示の状態を保持し、タブにマウスを重ねるとフルパスを表示します。通常表示と差分表示はそれぞれの表示位置を保持します。切り替え時にファイルや差分を読み直すため、非表示中の外部変更も反映します。別のフォルダーはプロジェクト一覧へ追加します。登録済みのフォルダーは同じプロジェクトを選び、ツリー・タブ・本文・入力先をメモリから表示します。切り替え時にSQLiteやGitの完了を待ちません。

Gitはブランチ、変更数、未追跡ファイル数を表示します。エクスプローラーとGit一覧では、状態は名前の色で示し、状態記号は付けません。追加・未追跡は緑、削除・競合は赤、変更・リネームなどは黄で表示し、選択中も状態の色を保持します。エクスプローラーのフォルダー名に末尾の区切り文字は付けません。Gitサイドバーの`Tree` / `List`で変更一覧の表示を切り替えられます。初期状態のListは作業フォルダーからの相対パスを一覧表示し、TreeはGitリポジトリのルートを基準に、変更ファイルを親フォルダーごとにまとめます。Treeのフォルダーは矢印やダブルクリック、左右矢印・Enter・Spaceで展開・折りたたみでき、更新や表示の切り替えでも折りたたみ状態を保持します。表示形式はプロジェクトごとに保存し、再起動後も復元します。削除済みファイルも両方の表示から差分を開けます。未追跡ディレクトリの中もファイル単位で一覧に含めます。差分はまず作業ツリーを表示し、差分がなければステージ済みの差分を表示します。未追跡ファイルは通常のファイル表示を使います。コミット・ステージ操作はターミナルで行います。

差分は初期状態では変更前を左、変更後を右に並べ、各ファイルの行番号を表示します。見出しの`Split` / `Inline`またはF7でインライン表示に切り替えられます。インラインでは削除行、追加行を順に1列へ並べ、変更前・変更後の行番号を2列で表示します。共通行は1回だけ表示します。削除行は薄い赤、追加行は薄い緑の背景で示し、文字色は通常色を使います。左右比較のスクロールは同期します。Gitのヘッダーや`@@`などのメタ情報、行頭の差分記号は表示しません。選択・コピーは左右比較では選んだ側、インラインでは表示された削除・追加行を含む本文が対象です。表示形式はプロジェクト単位で保存し、同じプロジェクト内のすべての差分タブに共通で適用します。ファイルの切り替えや再起動後も選んだ形式を使い、形式の切り替え時には表示中の行をできるだけ維持します。表示するのは変更箇所とその前後の行で、離れた変更箇所では行番号が飛びます。バイナリーやファイル属性だけの変更など、本文の差分がない場合は案内を表示します。

AIなどによるフォルダー内の変更を検知し、500 msの待ち合わせ後に再取得します。変更が続く場合は約2秒ごとに更新を依頼します。OS通知が利用できない場合や作業フォルダー外での変更は、F5で更新できます。読み込み中の新しい結果が届くまで時間がかかる場合があります。

各プロジェクトが専用の複数ターミナルを持ちます。非表示でもConPTYの受信・VT解析・応答を続け、再選択時に同じプロセスと画面を表示します。通常のシェルは所属プロジェクトのフォルダーで起動します。ターミナルを閉じると対象のプロセスと子プロセスを終了します。ai-containerの停止にはホスト側アダプターの終了要求を使い、確認できない場合は終了未確認と表示します。

## 作業領域と前回状態の復元

保存先は `%APPDATA%\yumayo\Poppy` です。`APPDATA` が未設定の環境ではWindowsのRoaming AppDataフォルダーを使います。

```text
%APPDATA%\yumayo\Poppy\
  storage.sql
  projects\
    -d-repository-yumayo-poppyworktrees-poppydirect2d\
      storage.sql
```

全体の `storage.sql` はSQLite3のデータベースで、前回のプロジェクト、ウィンドウの位置・大きさ・最大化状態、プロジェクトと保存先の対応を管理します。プロジェクトごとの `storage.sql` には共通の差分表示形式（Split／Inline）、タブの順序と選択、各タブの表示位置・選択範囲・通常／差分表示、エクスプローラーの展開と選択、サイドバーの種類と幅、ターミナルの表示と高さを保存します。開いている一覧と選択・一覧幅、各ペインの選択とスクロール、Gitの折りたたみ、ターミナルID・名前・順序・起動フォルダーも保存します。操作後650 msの待ち合わせを経て、専用ワーカーがSQLite接続を所有して保存します。プロジェクトの切り替えは保存を待ちません。終了時は非表示プロジェクトも保存します。

プロジェクトの保存先名は絶対パスを小文字にして区切り文字などをハイフンへ置き換えます。同じ名前になる別のパスにはハッシュの接尾辞を付け、既存の保存先と分けます。長い名前は短縮してハッシュを付けます。再起動時は通常表示のファイルが削除されていればそのタブを除外し、削除ファイルの差分タブは復元します。ターミナルの実行プロセスや出力履歴は復元せず、次に操作したときに新しいPowerShellを起動します。

保存はトランザクションで行い、プロジェクトの保存中に失敗した場合は前回の状態を残します。読み込み・保存に失敗した場合はメッセージを表示します。より新しいバージョンの保存形式は上書きしません。

保存先の命名規則、SQLiteのテーブルとカラム、保存・復元の流れは [DATASTRUCTURE.md](DATASTRUCTURE.md) にまとめています。

## メモリを抑える構成

- ファイルツリーは展開した階層だけ列挙し、折りたたんだ配下のノードを解放します。`.git`は表示せず、ディレクトリのリンク・ジャンクションは再帰展開しません。
- 各プロジェクトで最後に表示した本文を保持し、全体64 MiBを超えた場合は古い非表示プロジェクトの本文から解放します。解放後はタブと位置を先に表示し、本文を非同期で読み直します。各プロジェクト内では表示中のファイル本文だけを保持します。非表示タブにはファイルパス・表示位置・選択範囲・差分表示の状態だけを残し、切り替え時に本文を読み直します。本文のUTF-8スナップショットと行頭位置・行ごとの字句状態を保持し、表示行のトークンと描画用文字列をその場で作ります。Ctrl+P用に全ファイルの相対パスと検索用の正規化済みパスを保持しますが、非表示ファイルの本文や全行の描画キャッシュは保持しません。
- ディスクI/OとGitは別のワーカーで処理し、UIスレッドでファイル走査やGitの終了待ちを行いません。古い読み込み結果を表示しないよう世代と要求番号を確認します。
- シェルは操作時に起動します。ターミナルは固定セルの画面と上限付き履歴を持ち、外部ターミナルアプリを埋め込む構成にはしません。
- 大量のターミナル出力は8 KiB単位で全セッションを順番に処理し、時間が残っていれば同じ回で続きを解析します。全体の解析時間を約16 msあたり5 ms以内に制限し、続きを共有タイマーで処理します。表示が追いつかない場合は出力側を待機させ、メモリ増加とUIの占有を抑えます。
- ターミナルの表示は確定した可視画面を保持し、連続する出力は32 msの待ち合わせでまとめます。リサイズ後は100 ms待ち、出力やリサイズが続く場合も120 msごとに表示を更新します。同期更新の指定中は終了指定まで画面を保持し、終了指定が欠けた場合は1秒で解除します。再表示・フォーカス変更やコピーにも表示用の画面を使い、表示更新を待っている間の途中経過が現れないようにします。
- ディレクトリー変更の完了イベントは80 msの共有タイマーで確認し、プロジェクト数をUIの待機ハンドル数に直結させません。Gitの常時取得は行わず、変更通知、選択時、再アクティブ時、F5で再検証します。

| 項目 | 初期上限 |
| --- | --- |
| ファイル | 読み込み時・UTF-8変換後ともに16 MiB / 1,000,000行 |
| 長い行の表示 | 先頭8,192桁まで。コピー対象には全文が残る |
| ファイルツリー | 1フォルダー10,000件 / 全体50,000ノード |
| Git変更ファイル一覧 / 状態の色分け | 50,000ファイル / 親ディレクトリを含め50,000パス |
| GitのTree表示の親フォルダー | 最大50,000ノード。上限を超える階層は残りの相対パスをファイル名として表示する |
| Gitコマンドの出力 | 1回4 MiB / 差分は1,000,000行まで |
| ターミナル画面 | 最大500列 × 200行 × 通常・代替の2画面 |
| ターミナル表示用画面 | 最大500列 × 200行の1画面。履歴は複製しない |
| ターミナル履歴 | 最大1,000行、かつ131,072セル。セル領域は約2 MiB以内 |
| ターミナル受信待ち | 256 KiB。超過時はパイプ読み取りを待機する |
| ターミナル送信待ち | 1 MiB。超過する入力は受け付けない |

これらはアプリ全体のメモリ上限ではありません。読み込み中の旧・新ファイル、UTF-16変換、コピー、Gitの結果入れ替えなどで一時的な追加領域を使用します。Windowsの共有DLL、ツリーの階層・表示位置とラベル幅のキャッシュ、Direct2Dの描画先やGPUドライバーの領域も必要です。PowerShell・AI CLI・Gitは別プロセスでメモリを使います。

## 初版の表示範囲

ファイル表示はUTF-8、BOM付きUTF-16 LE / BEに対応します。バイナリーやShift_JISなどはプレビュー対象外です。簡易シンタックスハイライトはC/C++、C#、JavaScript/TypeScript、Rust、Go、JavaなどのC系構文、Python、シェル、JSON、TOML/YAML/INI、Git差分を対象とします。言語の完全な構文解析は行いません。

ターミナルはConPTYのUTF-8出力を受け取り、基本的なカーソル移動、行・文字の挿入と削除、スクロール領域、代替画面、16/256/true color、bracketed paste、カーソル・背景色の照会、同期更新（DEC private mode 2026）の開始・終了と状態照会に対応する小さなVT実装です。日本語などの全角文字とIMEの確定文字列を扱うコードを含みます。

Windows Terminal相当の互換性はまだありません。結合文字・ZWJ絵文字の合成、文字装飾の完全再現、マウスプロトコル、画像、Kittyキーボードプロトコル、履歴の折り返し再計算は未対応です。使うAI CLIで表示と操作を確認する必要があります。

## 検証と計測

`tests/core_tests.cpp`は、エンコーディング、不正・分割UTF-8、複数行ハイライト、分割VTシーケンス、色、全角文字の上書き、画面切り替え、スクロール領域、入力モード、履歴上限、リサイズを検証するテストです。同期更新の状態照会、分割された開始・終了指定、履歴の再出力中の画面保持、終了指定の欠落、プロセス終了時の表示確定、大量出力・連続リサイズの表示待ち時間の上限も検証します。

`tests/tree_tests.cpp`はWindowsに依存しないツリーモデルのテストです。階層の展開・折りたたみ、空フォルダー、選択の復元、並べ替え、子ノードの解放、削除したIDの再利用防止、50,000件の子ノード、10,000階層の走査・削除を検証します。GitのTree／Listについて、同名ファイル・日本語パス・共有フォルダーの階層とファイル対応、フォルダー優先の並び、空の一覧、フォルダー上限でもファイルが残ること、50,000ファイルの構築も検証します。

`tests/ai_status_tests.cpp`はAIの状態遷移・集約・通知形式を、`python3 tests/hook_scripts_tests.py`はhookの導入と解除を検証します。`tests/session_tests.cpp`はプロジェクトの保存先名を検証します。SQLiteが利用できる場合は `tests/storage_tests.cpp` も実行し、日本語パスを含む保存と再読み込み、プロジェクトの分離、保存先名の衝突、保存失敗時のロールバック、新しい保存形式の保護を検証します。SQLiteがないLinux環境では保存テストを省略してコアテストだけを実行します。

Windowsで`BUILD_TESTING=ON`にしてビルドすると、`tests/render_tests.cpp`も`ctest`に追加されます。WICのビットマップとテスト用ウィンドウを使い、日本語・サロゲートペア・右から左へ書く文字を含む行のセル位置、フォントのベースライン、背景色、クリッピング、DPI変更、リサイズ、描画先の再作成と切り替えを検証します。スクロールバーの背景・通常・ホバー・ドラッグ中の配色、縦横のドラッグ、65,535を超えるスクロール位置、矢印・ページ操作、操作のキャンセル、非表示時の表示領域の復元も検証します。長い行の縦横ドラッグとホイール操作について、入力が続いている間も新しいスクロール位置で再描画することを確認します。このテストではウィンドウを表示します。Windows上で実行するテストで、Linux上のクロスビルドでは実行しません。

Windowsで`BUILD_TESTING=ON`にしてビルドすると、`ctest`で`tests/folder_tests.cpp`も実行します。日本語・空白を含む一時フォルダーでPoppyを起動し、フォルダーを開いた直後の表示、子フォルダーの展開・折りたたみ・再展開、空のフォルダーやワークスペースへのファイル追加後の表示を検証します。独自ツリーの矢印・ページ移動・文字検索・縦横スクロール、独自ボタンのマウス・Enter・Space操作と押下のキャンセル、サイドバー切り替え、非表示中の更新、境界のドラッグも検証します。タブの切り替え、縦横のスクロール位置の復元、既存タブの再選択、非表示中のファイル変更の反映、タブを閉じる操作、読み込み中のクローズ、複数段への折り返し、クローズ・リサイズによる段数の調整、高さに収まらないタブの送り操作も対象です。テスト中はPoppyのウィンドウが開くため、デスクトップを利用できるWindows環境で実行してください。

タブのドラッグについては、幅の異なるタブの前後移動、行の空白部分へのドロップ、複数段をまたぐ移動、ドラッグ中の段送り、固定タブ・通常タブそれぞれの並び替えと行の分離を検証します。Esc・キャプチャ喪失・領域外でのキャンセル、移動後の表示位置の保持、再起動後の順序・選択・固定状態の復元も対象です。

GUIテストは一時フォルダーを `APPDATA` に設定し、通常利用の保存状態に影響させません。再起動後の前回プロジェクト・タブ・表示位置・ツリー展開・ペイン配置の復元、削除されたファイルの除外、ルートを折りたたんだ状態の保持も検証します。Git for WindowsがPATHにある場合は、一時リポジトリでGitのTree／Listの切り替え、同名ファイルの表示、更新後の折りたたみ状態、再起動後の表示形式の復元も検証します。

WindowsではReleaseビルド後、次の順で確認します。

1. フォルダー展開・折りたたみ、ファイル切り替え、スクロール、選択とコピーを確認する。
2. 小さいファイル、日本語ファイル、空ファイル、16 MiB超のファイル、非常に長い行を表示する。
3. Gitの未追跡・変更・ステージ済み・競合・リネームの表示と差分を確認する。
4. AI CLIを起動し、日本語IME、ペースト、Ctrl+C、代替画面、リサイズ、resumeによる履歴の再出力、継続的な大量出力を確認する。再描画中のフォーカス変更・再表示でも途中の画面が現れないこと、同期更新の終了指定が欠けても表示が再開することを確認する。
5. 外部でファイルを変更・作成・削除・置換し、表示更新を確認する。
6. 大量出力中、ペースト中、Git実行中にアプリを閉じ、停止や子プロセスの残留がないことを確認する。
7. 100% / 150% / 200%表示倍率とモニター間移動を確認する。

メモリ計測用スクリプトも用意しています。

```powershell
$app = Start-Process .\out\Release\Poppy.exe -PassThru
.\scripts\measure-memory.ps1 -ProcessId $app.Id -Samples 30 -CsvPath idle.csv
# フォルダー・ファイルを開いた後にも同じように計測する
.\scripts\measure-memory.ps1 -ProcessId $app.Id -Samples 30 -CsvPath viewer.csv
# AI CLIを動かした状態で子プロセスも含めて計測する
.\scripts\measure-memory.ps1 -ProcessId $app.Id -Samples 30 -IncludeChildren -CsvPath with-ai.csv
```

Working Setはその時点で物理メモリに載っている領域、Private Bytesはプロセス専用のコミット量です。スクリプトは両方の平均とサンプル内最大値を出します。瞬間的なピークを取りこぼす場合があります。Poppy単体と、AI CLIなどを含む合計を分けて記録してください。計測のためにWorking Setを強制的に削る処理は行いません。

## Editorでの修正

通常のファイル表示で文字入力、日本語IME、選択置換、Enter、Tab、Backspace / Delete、矢印・Home / End・Page Up / Down（Shiftで選択、Ctrl+Home / Endで先頭・末尾）が使えます。Ctrl+C / X / V、Ctrl+A、Ctrl+Z（Undo）、Ctrl+Y / Ctrl+Shift+Z（Redo）、Ctrl+S（保存）と右クリックメニューに対応します。Git差分は読み取り専用です。

未保存タブには `*` と `Modified` を表示します。タブ・プロジェクト切り替え、F5、AIによるファイル更新でも未保存本文を保持し、タブ・プロジェクト・アプリを閉じるときは保存・破棄・キャンセルを選択できます。未保存本文はメモリ内だけで保持し、異常終了からの復元は行いません。保存はUTF-8（BOM有無）、BOM付きUTF-16 LE / BEと既存改行を維持し、新規改行・貼り付けは最初の改行形式に合わせます。外部更新後の保存は拒否して編集を保持するため、必要な修正をコピーしてタブを閉じ、最新ファイルを開いて反映してください。一時ファイルを書き終えてから元ファイルを置換します。

ファイルは16 MiB・100万行未満、Undoは直近1,000操作・約16 MiBを目安に制限します。簡単な修正向けに各操作後に行索引とハイライト状態を更新します。未保存ファイルはメモリ回収の対象外です。

## Editor / Terminalの左右分割

タブを本文の左半分または右半分へドラッグすると、同じ領域に2つのタブグループを左右に並べます。EditorとTerminalはそれぞれ分割でき、各グループでファイル・セッションを切り替えられます。移動先の色付き領域を確認してマウスを離してください。既存グループのタブ見出しへドロップすれば、そのグループへの移動と並び替えができます。Esc、キャプチャ喪失、領域外へのドロップでキャンセルします。

中央の境界をドラッグすると左右の幅を変更します。片側の最後のタブを移動・クローズすると1グループへ戻ります。タブの所属、左右の選択、境界幅をプロジェクト単位で保存し、再起動後も復元します。Terminalの移動はConPTYを再起動しません。各グループの `+` で同じグループにシェルを追加でき、`+` の右クリックメニューからAIを起動できます。

## エクスプローラーの名前変更

ファイルやフォルダーを選んでF2、または右クリック → Renameを選びます。名前を入力してEnterで確定、Escや入力欄の外へのフォーカス移動でキャンセルします。ファイルは拡張子を除く部分を最初に選択します。プロジェクトのルートフォルダーは変更できません。既存の同名ファイルへの上書きは行いません。

成功すると開いているタブ、未保存本文の保存先、フォルダー配下のパス、ツリーの展開・選択、ファイル検索とGit一覧を更新します。Terminalの次回起動ディレクトリも追従します。実行中のシェルのカレントディレクトリは変更しません。権限不足や使用中のフォルダーなどの失敗はWindowsのエラーを表示します。
