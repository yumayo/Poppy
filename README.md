# Poppy

Windows専用の、AI CLIと一緒に使う小さなコードエディターです。左からプロジェクト一覧、編集可能なコード表示、エクスプローラー／Git／検索のサイドバー、アイコンだけのアクティビティーバーを配置し、既定ではコード表示の下にターミナルを置きます。ファイルとターミナルのタブは共通の領域へ自由に配置できます。AIに編集を任せながら、人間による小さな修正も行えます。

サイドバーとアクティビティーバーの配置は、`src/layout_config.h`の`sidebarOnRight`で切り替えます。既定の`true`では右端からアクティビティーバー → サイドバー → Editorの順です。`false`に変更して再ビルドすると、従来の左からアクティビティーバー → サイドバー → Editorの配置に戻ります。

C++17 / Win32 / Direct2D / DirectWrite / ConPTYで実装しています。HTMLのプレビューには初回にWebView2を起動し、Sourceへの切り替えやタブの切り替え後も保持して、次のプレビューで再利用します。Node.js、.NETランタイム、外部のエディターエンジンは使用しません。LSP、拡張機能は入れていません。

コードビューアー、ターミナル、タブ、ファイルツリー、Git一覧、アクティビティーボタン、スクロールバーをDirect2Dで描画し、文字の整形とフォントのフォールバックはDirectWriteを使います。アイコンはDirect2Dのベクターパスを使い、図形のアンチエイリアスと丸い線端・結合で滑らかに描画します。ツリーとボタンも独自のウィンドウで描画し、アプリからGDIの描画・フォントAPIを呼び出したり、`gdi32`へ直接リンクしたりする処理はありません。描画テストのビットマップにはWICを使います。スクロールバーはアプリの暗いテーマに合わせ、通常・ホバー・ドラッグ中の色を切り替えます。メニューと通常のツールチップはWindows標準UIを使い、コピー可能なコミットメッセージのポップアップは独自に描画します。

コードとターミナルは全角文字を含めて固定セルの位置に描画します。ウィンドウの描画先はハードウェア描画を優先し、作成できない場合はDirect2Dのソフトウェア描画を使います。リサイズとモニターごとのDPI変更に対応し、描画リソースの喪失時は描画先を再作成します。Direct2D、DirectWrite、WICはWindowsに含まれるため、配布用の追加ランタイムは不要です。

**初期実装です。Windows上での動作、実際のAI CLIとの互換性、メモリ使用量は未検証です。** Docker上でのWindows向けクロスビルドとLinux用コアテストは実行済みです。メモリ使用量の達成値は記載していません。

## ビルド

生成するアプリはWindows 10 version 1809以降のx64環境が対象です。WindowsプロジェクトのGit表示には、別途Git for WindowsをPATHに追加してください。WSLプロジェクトは選んだディストリビューションのGitを使います。AI CLIも利用する環境へ別途インストールします。

状態の保存にはSQLite3を使います。SQLite3はC++標準ライブラリには含まれません。`third_party/` はGit管理対象外のため、ビルド前に [SQLite公式サイト](https://sqlite.org/download.html) の `sqlite-amalgamation-*.zip` から、同じリリースの `sqlite3.c` と `sqlite3.h` を `third_party/sqlite/` に配置してください。SQLite 3.54.1でビルドと保存テストを確認しています。CMakeで静的リンクするため、配布先にSQLiteのDLLを追加する必要はありません。

Windows向けビルドにはMicrosoft.Web.WebView2 SDK 1.0.4314.35も必要です。NuGetパッケージを`third_party/microsoft.web.webview2.1.0.4314.35/`へ展開し、`build/native/include/WebView2.h`と`build/native/x64/WebView2Loader.dll`がある状態にしてください。別の場所を使う場合はCMakeの`POPPY_WEBVIEW2_SDK`で指定します。CMakeはアーキテクチャに合う`WebView2Loader.dll`とライセンス・NOTICEを本体DLLと同じリリースフォルダーへコピーします。配布時もこれらを同梱してください。HTMLプレビューを使うWindowsにはMicrosoft Edge WebView2 Runtimeが必要です。SDKとLoader DLLだけではブラウザー本体は含まれません。

### Dockerでビルド

GNU Makeを用意し、Docker DesktopをLinuxコンテナモードで起動して、リポジトリのルートで実行します。ホスト側のVisual StudioやCMakeは不要です。

```sh
make dev
make artifact
```

`make dev`は`docker compose up -d --build dev`を実行し、`poppy-dev`コンテナを常駐させます。Dockerの再起動後も自動起動します。明示的に停止した場合は`make dev`で再開できます。

`make artifact`は`dev`を起動した後、`docker compose exec -T dev /usr/local/bin/poppy-build`を実行します。Docker内でLinux用のコアテストを実行した後、MinGW-w64でWindows x64向けReleaseビルドを行い、`out/docker/live/`へ配信します。起動用の`Poppy.exe`は初回だけ配置し、以降は本体DLLと依存ファイルを別のリリースフォルダーへ追加して、次回の起動先を切り替えます。既存の`out/docker/Poppy.exe`は変更しません。ビルド終了後もコンテナは起動したままです。C++とwinpthreadsのランタイムは静的リンクします。生成した起動用実行ファイルをWindows上で起動してください。

```powershell
.\out\docker\live\Poppy.exe --project "C:\work\project"
```

初回のイメージ作成にはDocker HubとDebianパッケージ配布元への接続が必要です。イメージ作成後のテスト・コンパイルは、外部接続できない内部ネットワーク（`internal: true`）で実行します。ソースを読み取り専用でマウントし、中間生成物はComposeの`build-cache`ボリューム、完成した実行ファイルはホストの`out/docker`に保存します。並列コンパイル数は既定で2、`POPPY_BUILD_JOBS`環境変数で変更できます。

`docker/build.sh`はイメージ作成時に`/usr/local/bin/poppy-build`へコピーし、実行権限`0555`で固定します。コンテナのルートファイルシステムも読み取り専用にし、実行中のスクリプト差し替えを防ぎます。ビルドには書き込み可能な`/build`・`/output`と、一時ファイル用の`/tmp`（tmpfs）を使います。リポジトリ側の`docker/build.sh`を編集しても、ホストで`make dev`を実行してイメージを再ビルドするまで、許可済みの実行内容は変わりません。

コンテナを停止する場合は`docker compose stop dev`、削除する場合は`docker compose down`を実行します。中間生成物のキャッシュも破棄して作り直す場合は、`docker compose down --volumes`を実行します。旧`build`サービスから移行する場合は、`docker compose down --remove-orphans --volumes`で旧コンテナと旧マウント先を記録したCMakeキャッシュを削除してから、`make dev`を実行してください。

コンテナ内で実行するテストはLinux版のコアテストです。Windows実行ファイルの起動、GUI、ConPTYの動作確認はWindows実機で行います。

### AIコンテナからビルド・コンパイルチェック

ホスト側のWSL / Linuxでリポジトリのルートから`make dev`を実行し、`.aicontainer`に次の設定を追加します。

```ini
docker-proxy-name=poppy-docker-proxy
docker-proxy-containers=poppy-dev
docker-proxy-allow=sh /usr/local/bin/poppy-build
docker-proxy-allow=cmake
docker-proxy-allow=ctest
docker-proxy-allow=ninja
docker-proxy-allow=g++
docker-proxy-allow=x86_64-w64-mingw32-g++-posix
```

既存の`docker-proxy-allow=sh docker/build.sh`や`docker-proxy-allow=/usr/local/bin/poppy-build`は、上記の`sh`と固定パスを指定する設定に置き換えてください。設定を反映するため、AIコンテナを作り直して起動します。`.aicontainer`はローカル設定としてGit管理から除外されています。

AIコンテナ内でもリポジトリのルートから実行します。

```sh
# コアテストからWindows実行ファイルの生成まで実行
dp sh /usr/local/bin/poppy-build

# 初回ビルド後、Windows向けの差分コンパイルだけを実行
dp cmake --build /build/windows --parallel 2

# Linux用コアの差分コンパイルとテスト
dp cmake --build /build/linux --parallel 2
dp ctest --test-dir /build/linux --output-on-failure
```

旧イメージの固定スクリプトは従来の`out/docker/Poppy.exe`を更新するため、今回の`docker/build.sh`を反映するにはホストで`make dev`を実行してください。イメージ更新前でも、初回に次の設定を行えばCMake経由で新構成だけを配信できます。その後は上記の`dp cmake --build /build/windows --parallel 2`で更新できます。Linuxヘルパーは先にLinux用ビルドで生成してください。

```sh
dp cmake -S . -B /build/windows -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE="$PWD/cmake/mingw-w64-x86_64.cmake" \
  -DPOPPY_WSL_HELPER=/build/linux/poppy-wsl-helper \
  -DPOPPY_PUBLISH_DIR=/output/live \
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
dp cmake --build /build/windows --parallel 2
```

Composeはホストの`PWD`と同じ絶対パスにソースをマウントします。`dp`はAIコンテナの作業ディレクトリをそのまま引き継ぐため、`dev`とAIコンテナでリポジトリの絶対パスを揃えてください。

### Windowsで直接ビルド

Visual Studio 2022の「C++によるデスクトップ開発」、Windows SDK、CMakeを用意し、Developer PowerShellで実行します。

```powershell
cmake -S . -B out -A x64 -DBUILD_TESTING=ON
cmake --build out --config Release
ctest --test-dir out -C Release --output-on-failure
.\out\Release\live\Poppy.exe --project "C:\work\project"
```

フォルダー指定を省略すると開いていたプロジェクト一覧と選択を復元します。初回起動時は空のウィンドウが開きます。コマンドラインでフォルダーを指定した場合は、そのプロジェクトを優先します。起動済みの場合は既存のPoppyへ引数を渡し、ウィンドウを手前に表示します。Release版はCRTとSQLiteを静的リンクします。配布には`live/`内の起動用EXE、`current.txt`、`launcher-abi.txt`と対象の`releases/`を含めてください。通常利用にVisual StudioやCMakeは必要ありません。

### 起動したまま更新する

`Poppy.exe`は起動時に`current.txt`を読み、その版の`PoppyApp.dll`へ処理を渡す固定のランチャーです。既存の単体EXEからは、最初の一度だけ旧Poppyを終了し、`out/docker/live/Poppy.exe`を起動する構成へ移行してください。保存先は従来と同じため、プロジェクトやタブの復元を引き継ぎます。以降の更新で配信済みの`Poppy.exe`を書き換える処理はありません。

```text
live/
  Poppy.exe                 ← 初回だけ配置するランチャー
  launcher-abi.txt
  current.txt               ← 次回起動する版のID
  releases/
    <旧版のID>/             ← 起動中はそのまま使う
    <新版のID>/
      PoppyApp.dll
      PoppyTerminalHost.exe     ← 実行中のTerminalを保持
      WebView2Loader.dll
      WebView2-LICENSE.txt
      WebView2-NOTICE.txt
      wsl/poppy-wsl-helper   ← POPPY_WSL_HELPER指定時
      ai/
```

Poppyを開いたまま`make artifact`または`dp cmake --build /build/windows --parallel 2`を実行できます。更新処理は本体DLL・WebView2・WSLヘルパー・AI連携ファイルを一時フォルダーへ揃え、内容のハッシュをIDにしたリリースフォルダーへ移してから、最後に`current.txt`を同一ディレクトリ内で原子的に差し替えます。コピー中に起動しても旧版を読み込み、コピーが失敗した場合は起動先を変更しません。同じ内容の再ビルドでは同じリリースを再利用します。

起動中のPoppyは、本体DLLのある旧版のフォルダーからWebView2とWSLヘルパーを読み続けます。別の版が配信されると、約2秒間隔の確認でタイトルバーの最小化ボタンのすぐ左に`Restart`を表示します。クリックすると未保存ファイルの確認後にプロジェクトやタブの状態を保存し、Terminalとの接続を切り離してから新版を起動します。シェル・AI CLI・コンテナは専用の`PoppyTerminalHost.exe`で動かし続け、新しいPoppyが同じセッションへ再接続します。画面、通常・代替画面、出力履歴、入力モード、スクロール位置、シェル内部の現在位置・変数、AI通知の状態を引き継ぎ、再起動中の出力も受け取ります。確認をキャンセルした場合は再起動しません。Alt+Spaceのシステムメニューにある`Restart to update Poppy`からも実行できます。

通常終了、ターミナルタブのクローズ、プロジェクトのクローズでは、従来どおり関連するWindows・WSL・コンテナの終了を待ちます。更新のRestartで保持したTerminalは、旧Poppyの終了後120秒以内に再接続されなければ終了処理へ進みます。専用ホストも起動元の旧リリースを使い続け、次にターミナルを起動し直すと新版へ切り替わります。この機能を持たない版からの初回更新では、既存のTerminalは従来どおり終了します。

Poppyを終了して同じ`live/Poppy.exe`を開く操作でも新版へ切り替わります。起動済みの状態でもう一度EXEを開く操作は、従来どおり既存ウィンドウを表示します。更新の自動ダウンロードや自動再起動は行わず、ビルドからのローカル配信に対応します。

配信先を変える場合はCMakeの`POPPY_PUBLISH_DIR`を指定します。直接ビルドの既定値は実行ファイルのビルド先にある`live/`です。ビルド用ランチャーは`PoppyLauncher.exe`という別名で生成し、従来のビルド先にある`Poppy.exe`も上書きしません。起動には配信先の`Poppy.exe`を使ってください。既存EXEがありランチャーの識別ファイルがない配信先は、上書きせずエラーにします。公開済みリリースは書き換えず、自動削除もしません。ディスク容量を整理する場合はPoppyを終了してから、`current.txt`のID以外のフォルダーを削除できます。元に戻す場合は、保持した旧版のIDを一時ファイルへ書いて`current.txt`と置き換え、Poppyを再起動します。

ランチャーと本体は固定のC ABI `PoppyMainV1`で接続します。通常の機能追加は本体DLL側で行い、ランチャーの更新を必要としない構成を維持します。Windowsの`poppy_launcher_tests`は、旧DLLを読み込んだまま起動先を切り替え、新しい起動だけが新DLLを使うこと、旧版のリソース・引数・作業ディレクトリが維持されることを検証します。ポータブルな`poppy_publish_tests`は、EXEと旧版の保持、配信失敗・中断時の起動先保持、依存ファイルだけの更新も検証します。`poppy_app_update_tests`は更新・取り下げ・不正な配信先・未完成の版の判定を検証します。Windowsの`poppy_single_instance_tests`には、再起動ボタンの表示位置、最大化・最小化・復元への追従、更新の取り下げと再配信、再起動後の版の切り替え、プロジェクト選択と同一シェル・変数の保持、通常終了時のシェル終了を確認するGUIテストがあります。このGUIテストの実行にはWindowsのデスクトップ環境が必要です。

### 起動引数

キーと値を `--project "ディレクトリ"` または `--project="ディレクトリ"` の形式で指定すると、Projectsへ追加して選択します。`--project` は繰り返し指定でき、最後に指定したプロジェクトを選択します。

```powershell
.\Poppy.exe --project "C:\work\project"
.\Poppy.exe --project="C:\work\project"
.\Poppy.exe --project "C:\work\first" --project "C:\work\second"
.\Poppy.exe --project ".\relative project"
.\Poppy.exe --project "\\wsl.localhost\Ubuntu\home\user\project"
```

同じWindowsセッション・保存先でPoppyが起動していれば、そのプロセスのProjectsへ追加し、呼び出したプロセスは終了します。既に開いているフォルダーは重複追加せず、その項目へ切り替えます。最小化していれば復帰します。引数なしで再起動した場合も既存のウィンドウを表示します。Poppyが起動していない場合は、保存済みプロジェクトを復元したうえで指定フォルダーを追加します。起動中の復元処理と重なった追加要求も保持します。

空白・日本語を含むパスは引用符で囲んでください。相対パスは呼び出し元のカレントディレクトリを基準に解決します。WindowsのフォルダーとWSLのUNCパス（例: `\\wsl.localhost\Ubuntu\home\user\project`）を指定できます。存在しないフォルダー、ファイル、空の値、未知の引数はエラーになります。従来の `Poppy.exe "C:\work\project"` も1フォルダーに限り利用できます。

起動済みプロセスが応答しない場合はエラーを表示します。通常の起動時と同じWindowsユーザー・権限で呼び出してください。

### コアテストだけを直接実行

Windows以外でも、ポータブルなテキスト処理・ターミナルモデル・ツリーモデルのテストをネイティブビルドできます。

```sh
cmake -S . -B out -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build out

```

## CSVテーブル

`.csv`を開くと、既定でExcel風の`Table`表示になります。列見出しはA、B、C…、行見出しは1、2、3…で、クリックやドラッグでセル・矩形範囲を選択できます。行番号・列見出しのクリックで行・列全体、左上の角またはCtrl+Aで表全体を選びます。列の境界はドラッグして幅を変更できます。見出しは縦横スクロール中も固定し、Shift+ホイールで横へスクロールできます。

| 操作 | 動作 |
| --- | --- |
| 矢印／Shift+矢印 | セル移動／範囲の拡張 |
| Tab／Shift+Tab | 次／前のセルへ移動 |
| Enter／Shift+Enter | 下／上のセルへ移動 |
| Home／End、Ctrl+Home／End | 行の先頭／末尾、表の先頭／末尾へ移動 |
| ダブルクリック／F2／上部の値欄をクリック | 選択セルの値を編集 |
| 文字入力／Backspace | セルの値を置き換える編集を開始 |
| 編集中のEnter／Escape | 編集を確定／取り消し |
| 編集中のAlt+Enter | セル内に改行を挿入 |
| Delete | 選択範囲の値を消去 |
| Ctrl+C／X／V | セル範囲のコピー／切り取り／貼り付け |
| Ctrl+Z／Y、Ctrl+Shift+Z | セル単位で元に戻す／やり直す |
| Ctrl+S | 元のファイルへ保存 |

Excelとのコピー・貼り付けにはタブ区切りを使い、複数行・複数列の範囲とセル内のタブ・改行・引用符を保持します。単一の値を選択範囲へ貼り付けると、その範囲を同じ値で埋めます。編集中の貼り付けはすべて1セルの値として挿入します。表の末尾にある空の行・列へ入力するとデータを追加できます。

カンマ区切り、引用符内のカンマ・改行、`""`でエスケープした引用符、列数の異なる行に対応します。値は文字列のまま扱うため、`001`などの先頭ゼロも保持します。数式の計算や日付・数値への自動変換は行いません。保存には既存エディターと同じバッファを使い、UTF-8／UTF-16・BOMを保持します。変更していないセルの引用符と既存の行区切りも保持します。

タブ右端の`Source`でCSV本文へ切り替え、`Table`で表に戻ります。未保存本文とUndo履歴は共通です。Ctrl+F／F3とプロジェクト検索の結果はSourceで表示します。Git差分とコミット時点の表示は従来のテキスト表示を使います。CSVの構文が不正、または表の上限（合計100万セル・16,384列）を超える場合はTableに理由を表示し、Sourceで確認・修正できます。Table／Sourceの選択と列幅はアプリ終了時には保存しません。同じCSVを表示状態を保って再読み込みするときは、選択した表示を維持します。

`tests/csv_tests.cpp`はCSV／クリップボードの解析、矩形編集、引用符・改行・エンコーディングの保持とセル単位のUndoを検証します。`tests/render_tests.cpp`には100%／150%／200%のDPIでのセル選択・編集・コピー・貼り付け・列幅変更・表示切り替えのGUIテストがあり、実行にはWindowsのデスクトップ環境が必要です。

## HTMLプレビュー

`.html` / `.htm`を開くと、既定で`Preview`を選択し、Poppy内にWebView2でHTMLとして描画します。エディターのタブ領域右端にある`Source`で編集画面へ切り替えます。左右分割した各エディターでもタブ領域右端に配置し、本文とプレビューはタブの直下から表示します。プレビューはディスク上のファイルを対象とするため、編集後はCtrl+Sで保存してから`Preview`を使ってください。再読み込みするときは`Source`から`Preview`へ切り替えます。ソースの未保存本文・Undo履歴・選択位置は切り替え後も保持します。

`file://`で開くため、相対パスのCSS・画像も読み込めます。JavaScriptは既定で無効にし、ページ内のスクリプトを実行せずにHTMLを描画します。WSLのHTMLは`\\wsl.localhost`共有経由で開き、Windows側のアクセス権を使います。名前にバックスラッシュを含むWSLパスは表示できません。Git差分・コミット時点の表示にはプレビューを付けません。プレビューの表示状態は保存せず、別のHTMLタブを開くとPreviewから始まります。同じHTMLを表示状態を保って再読み込みするときは、選択中のSource／Previewを維持します。

WebView2はプロジェクトごとに初めて`Preview`を使ったときに起動し、`Source`や別タブへの切り替えでは終了しません。同じコントローラーで次のHTMLを開くため、2回目以降のプレビューでエンジンの初期化を省けます。非表示にすると`about:blank`へ移動して元のページのスクリプトや音声を終了しますが、WebView2本体のメモリは保持します。プロジェクトを閉じるかPoppyを終了すると解放します。

WebView2のユーザーデータは`%LOCALAPPDATA%\Poppy\WebView2`に保存します。Runtime・Loaderがない場合や読み込みに失敗した場合はプレビュー領域にエラーを表示し、`Source`から編集を続けられます。

Windowsで`BUILD_TESTING=ON`のビルド後、`poppy_render_tests.exe --html-preview-runtime`でWebView2の再利用とJavaScriptが実行されないことを検証できます。WebView2 Runtimeとデスクトップ環境が必要です。初期化中のSource切り替え、別HTMLへの移動、連続切り替え、エラーからの復帰で同じコントローラーのウィンドウが保持され、終了時には破棄されることを確認します。通常の描画テストはRuntimeなしでも実行できます。

`tests/folder_tests.cpp`ではタブ右端のSource／Previewのクリック・ダブルクリック、タブとの重なり防止、通常ファイルへの切り替え、左右ペインごとの切り替えを検証します。`tests/render_tests.cpp`では100% / 150% / 200%のDPIで、見出し行を削除した本文と検索欄の位置、プレビュー前後の未保存本文・選択・Undo履歴の保持を確認します。これらのGUIテストの実行にはWindows環境が必要です。

## 複数プロジェクトとAI状態

ウィンドウのタイトルは常に`Poppy`です。プロジェクト画面は上部ツールバーを置かず、サイドバーとエディターを上端から表示します。フォルダーを開く操作はCtrl+O、再取得はF5、差分切り替えはF6、下段の表示切り替えはCtrl+J、ファイル検索はCtrl+Pを使います。

PROJECTS見出しの右端にある「＋」（Open folder）またはCtrl+Oで、現在のプロジェクトを残して追加します。左端にはプロジェクトごとに余白を空けた角丸のカードを表示し、クリックして切り替えます。選択中のカードは緑色の枠で示します。一覧の境界はドラッグで調整でき、カードの右クリックまたは中クリックで対象プロジェクトを閉じます。フォルダーやworktree自体は削除しません。同名フォルダーには識別できる親パスを補助表示します。WSLの接続情報はタイトルと同じ行の右側に表示します。

PROJECTS見出しの左端の矢印、または選択中のプロジェクト名のクリックで一覧を折りたたみ・展開できます。折りたたみ時はプロジェクト名の先頭一文字とAI状態アイコン、未読の印を表示します。未選択のカードはAI状態アイコンや余白を含むカード全体のどこをクリックしても、そのプロジェクトへ切り替え、一覧は折りたたんだままにします。選択中のカードをクリックすると一覧を展開します。名前全体・パス・AIからのメッセージはツールチップで確認できます。展開時のAI状態アイコンのクリックでは対象端末へ移動し、ドラッグでは並び替えます。折りたたみ状態と展開時の幅は再起動後も復元します。

PROJECTSのカードは左ドラッグで並び替えられます。カード間に表示する挿入位置の線を目印にマウスを離してください。一覧の上下端に重ねると自動スクロールし、隠れている位置へも移動できます。Esc、キャプチャ喪失、一覧の外でのドロップはキャンセルします。順序は再起動後も復元します。

PROJECTSのカードが表示領域に収まらない場合は、見出しの下から一覧の右端にスクロールバーを表示します。ホイールに加え、つまみのドラッグ・上下の矢印・トラックのクリックで移動できます。プロジェクトの選択や並び替え中の自動スクロールにも追従し、ウィンドウの拡大やプロジェクトの終了ですべてのカードが収まると非表示になります。

閉じたプロジェクトも履歴に残り、Ctrl+Rまたは「Open folder」の「Recent projects…」から再び開けます。名前・パスで絞り込み、↑↓とEnter、または行のクリックで選択します。Escや外側のクリックで閉じます。同名フォルダーにはフルパス、WSLにはディストリビューションとユーザーも表示します。既に開いているプロジェクトはそのまま選択し、閉じたものは保存済みのタブや配置を復元します。すべてのプロジェクトを閉じて終了しても、履歴は次回起動時に残ります。

「Open WSL folder…」では、エクスプローラーと同じWindows標準のフォルダー選択で`\\wsl.localhost`配下を辿り、WSLのプロジェクトを開けます。アドレスバーへのパスの貼り付けと、接続ユーザーの指定もできます。ファイル表示・編集・保存・名前変更・検索・Git・ターミナルに対応し、Windowsのプロジェクトと同時に利用できます。配布時は`wsl/poppy-wsl-helper`を対象リリースの`PoppyApp.dll`と同じフォルダーに同梱してください。接続・保存の制約と検証範囲は [WSL対応](docs/wsl-support.md) を参照してください。

ターミナル領域の「＋」でシェルを追加し、タブで切り替えます。ターミナルタブの右クリックで名前変更・終了、「＋」の右クリックでCodex・Claude Codeをai-containerで起動できます。設定手順は [ai-container連携](integration/ai/README.md)、所有関係と検証範囲は [実装メモ](docs/multi-project.md) を参照してください。再起動後は構成だけを復元し、以前のAIコマンドを自動実行しません。

Windowsプロジェクトでは「＋」右隣の展開アイコンから`PowerShell` / `Git Bash`を選んで追加できます。同じメニューの`Default shell for this project`で「＋」が使うシェルを選択します。初期値はPowerShellで、デフォルトと各タブのシェル種別はプロジェクトごとに保存されます。デフォルトの変更は新しく追加するターミナルに反映されます。Git BashはGit for Windowsを`C:\Program Files\Git\bin\bash.exe`にインストールして利用し、プロジェクトのフォルダーで対話ログインシェルを起動します。起動できない場合はターミナルにパスとエラーを表示します。WSLプロジェクトの展開メニューではLinuxシェルとAI起動を選択できます。

PowerShell・Git Bash・WSLのすべてのターミナルで、入力に対する応答と通常出力は受信・解析後にその場で描画します。16msの描画間隔、出力が止まるまでの待ち合わせ、リサイズ後の待機は設けません。ターミナルのDirect2D描画も垂直同期を待たずに提出します。実際の画面への反映はWindowsの合成処理とモニターの更新周期に従います。アプリが明示的に指定する同期更新（DEC private mode 2026）中だけ、終了指定まで画面を保持します。

ターミナルはタブの直下から本文を表示します。終了したセッションはEnterで再起動できます。

ターミナルに表示された`http://`／`https://`のURLは、左クリックでWindowsの既定ブラウザーに開けます。マウスを重ねると手の形のカーソルになり、ドラッグした場合は従来どおり文字を選択します。自動折り返し・履歴・ANSIの文字色にも対応し、自動折り返しの途中で表示範囲からはみ出すURLは開きません。

URLはASCII形式（日本語などはパーセントエンコード）を対象とし、ホスト名・IPv4／IPv6・ポートを検証します。空白・引用符・山括弧・バックスラッシュ・非ASCII文字、不正なパーセントエンコードや符号化された制御文字で読み取りを止めます。認証情報付き・ホストやポートが不正なURL、4,096文字を超えるURLは開きません。URLをコマンド文字列へ組み込まず、Windowsへ直接渡します。

起動中は`Starting terminal…`を表示し、通知用WSLの準備・ConPTYとシェルの作成をバックグラウンドで行います。PC起動後の初回にWSLの準備が遅い場合も、Poppyの画面操作を続けられます。起動中の入力は保持し、クリックを繰り返しても起動処理を重複させません。`tests/render_tests.cpp`に、準備待ち中のUI応答・入力保持・失敗後の再試行・起動途中の終了を確認するWindows用回帰テストがあります。実行にはWindowsのデスクトップ環境が必要です。

通常のターミナルタブは、シェルやCLIが通知するタイトル（OSC 0 / 2、BEL / ST終端）を表示します。タイトルが空、または通知前の場合はWindowsで選択したシェルの`PowerShell` / `Git Bash`、WSLで`WSL`を表示します。PowerShellでは`[Console]::Title = '作業名'`で変更できます。右クリックで付けた名前とAI起動時の`Codex` / `Claude`は優先し、`Shell`へ名前を戻すと自動表示に戻ります。自動タイトルは実行中のホストに保持し、更新のRestartでは引き継ぎます。通常終了後の新しいシェルでは初期表示に戻ります。タイトル通知は既存のOSC上限（コマンドを含め256バイト）内で受け付けます。

プロジェクトとターミナルの状態は、実行中・応答待ち・中断・完了を図形とツールチップで示します。未確認通知は状態とは別に保持し、対象端末を表示したときに消します。完了状態自体は残ります。プロジェクト名は最後の端末へ戻り、状態アイコンは代表状態の端末を開きます。Codexはローカル履歴を0.5秒ごとに読み、開始・完了・中断のhookを取りこぼしても表示を修復します。入力・承認待ちはhookで補助し、Claude Codeはhookで通知します。通常のシェルの生存や無出力時間からAI状態を推測しません。

PROJECTSの各カードのプロジェクト名の下には、AIから受信したメッセージを3行まで折り返して表示します。メッセージがない場合も3行分の領域を確保し、すべてのカードの高さを揃えます。複数のAIがある場合は代表状態のメッセージを表示し、同じ状態では状態の開始時刻が新しい端末を優先します。3行に収まらない受信メッセージはカードのツールチップで確認できます。

EXPLORERとSOURCE CONTROLの見出し右側にある`Collapse All`で、ルート・リポジトリ・ブランチ・変更グループ・コミット・フォルダーの階層をまとめて折りたたみます。既に閉じた親の下にある展開状態も解除し、再展開しても子フォルダーは閉じたままです。EXPLORERでは読み込み中の展開要求も取り消します。通常は背景を付けず、マウスを重ねたときだけ薄い白色の背景を表示します。

`tests/folder_tests.cpp`に、見出し右側のクリック、非表示の子階層・選択・スクロール位置、繰り返し操作、GitのTree／List切り替え・更新、再起動後の折りたたみ状態を確認するWindows用GUIテストがあります。`tests/render_tests.cpp`では折りたたみアイコンの各DPIでの描画も検証します。これらの実行にはWindowsのデスクトップ環境が必要です。

親フォルダーの下に複数のGitリポジトリがある場合も、その親フォルダーを開けます。たとえば `app/app-client/.git` と `app/app-server/.git` がある構成では `app` を開くと、SOURCE CONTROLにそれぞれのリポジトリとブランチを表示します。リポジトリの見出しには親フォルダーからの相対パスと現在のブランチを表示します。Windows・WSLの両方に対応します。

コミット履歴のファイル行では、`Open File`の左にある`Open Revision`で、そのコミット時点のファイル全体を読み取り専用で表示します。追加・変更された行は、そのコミットのdiffと同じ緑色の背景で表示し、削除行や赤色のマーカーは表示しません。変更のない前後の本文、折り返し、選択・コピー、ファイル内検索にも対応します。`Open File`は現在の作業ファイルを開きます。選んだコミットで削除されたファイルは、その時点の本文がない旨を表示します。

通常のエディターでも、GitのHEADから追加・変更された行の背景を変更ビューと同じ緑色で表示します。ステージ済み・未ステージ・未保存の編集を含み、編集・Undo／Redo・Gitの更新に追従します。追加・未追跡ファイルも対象で、無視されたファイルやGit管理外のファイルは着色しません。折り返した行は続きの部分も同じ背景色になります。

通常エディターの縦スクロールバー左側には、幅4px（表示倍率に追従）のマークでファイル全体のGit変更位置を表示します。追加・変更は緑、削除位置は赤で示し、画面外の変更も確認できます。本文と重ならない専用の領域に表示し、折り返し・リサイズ・編集・Undo／Redo・Gitの更新に追従します。長いファイルの小さな変更も見えるよう、マークには最小の高さを設けています。

つまみが最小サイズに広がる場合は、本文の表示範囲をつまみの高さへ拡大してマークを表示します。画面外にあるマークの位置と高さは同じ側にある間は固定し、表示範囲に入るマークだけが滑らかに拡大・縮小します。つまみ位置のピクセル単位の丸めを拡大計算に使わないため、離れたマークまで上下に往復することを防ぎます。通常の画面外の追加・変更マークは中央で消す代わりに、つまみの外側へ対応させます。本文に差分の着色がない場合だけは、削除位置のみのマークなどがつまみ中央半分に重なる部分を非表示にし、中央にマークがあれば本文にも差分が見える状態を保ちます。つまみの上下各1/4には画面外の変更マークが入る場合があります。位置計算・拡大中の動き・画面外マークの固定・中央部分の表示・削除・末尾・未保存編集の追従は`tests/diff_tests.cpp`で検証します。

`Changes`・`Staged Changes`の差分ビューでも同じ幅・色のスクロールバーマーカーを表示します。単一ファイルと`All Changes`のInline／Split表示に対応し、差分に表示している行全体を基準に位置を示します。Splitの置換行は緑、削除だけの行は赤、Inlineでは削除行を赤・追加行を緑で示します。ファイル名やメタデータの見出しにはマーカーを付けず、折り返し・リサイズ・表示形式の切り替え・編集・Undo／Redo・差分の再取得に追従します。差分の範囲と色、折り返し、ファイルの並べ替え・非表示、編集とステージ済みの表示の独立性を`tests/diff_tests.cpp`で検証します。

変更一覧のStaged Changes／Changes、ステージ・解除、All Changes、ブランチとコミット履歴、コミットの差分はリポジトリごとに扱います。同じファイル名やブランチ名でも操作先を分け、アイコンの変更数は全リポジトリの合計です。エクスプローラーからのF6も、そのファイルが属する最も内側のリポジトリを使います。`.git`がファイルになっているworktreeやサブモジュールも検出します。

リポジトリの検出は開いたフォルダー自身と子フォルダーを対象にし、開いたフォルダーより上位のリポジトリは含めません。子フォルダーを再帰走査し、`.git`の内部とディレクトリへのリンク／ジャンクションには入りません。最大5万ディレクトリ・20万エントリーを調べ、最大256リポジトリを表示します。変更ファイルの表示は全体で最大5万件です。検出・表示上限に達した場合はステータスに表示します。追加・削除はフォルダーの更新通知とF5で再検出します。

SOURCE CONTROLのアイコンには、変更ファイルと未追跡ファイルの合計をバッジ表示します。ステージ済み・未ステージの両方にあるファイルは1件と数え、変更が0件ならバッジを隠します。ファイルの保存・追加・削除・名前変更をファイルシステムの通知で検知し、一覧と件数を自動更新します。連続する変更は約500 ms待ってまとめ、変更が続く場合も約2秒ごとに更新します。SOURCE CONTROLを開いたときにもGitの状態を再取得します。Git hookの設定は不要です。

SOURCE CONTROL上部のリポジトリ欄でコミット先を選び、その下にメッセージを入力して`Commit`をクリックするか、入力欄でEnterを押すと、ステージ済みの変更をコミットします。未ステージ・未追跡ファイルやエディターの未保存内容は自動追加しません。入力は1行で、IMEの変換確定ではコミットしません。Windows・接続済みWSLに対応し、複数リポジトリの入力はそれぞれ保持します。

`Commit`の右側の下矢印をクリックすると`Commit (Amend)`を選べます。直前のコミットに現在のステージ内容を取り込み、入力したメッセージで置き換えます。入力が空なら既存のメッセージを維持し、ステージ変更がなくてもメッセージだけを変更できます。Amendは直前の履歴を書き換える操作です。通常コミットでは空のメッセージやステージ変更なしを拒否し、競合があればどちらの操作も停止します。Gitに設定されたユーザー情報・署名・hookを使い、失敗時はステータスにエラーを表示して入力を保持します。成功時は入力を空にし、変更一覧・件数・履歴・表示中の差分を更新します。入力は実行中だけ保持します。

AIはWSL内のDockerで`aicontainer codex`または`aicontainer claude`を実行して使います。WindowsプロジェクトのPowerShellでは、先に`wsl`へ入り、同じコマンドを実行します。通知ソケットはPoppyが自動設定します。導入・更新方法は[AI連携手順](integration/ai/README.md)を参照してください。プロバイダーのAPIキーをアプリ側で管理する機能はありません。PowerShellは`-NoProfile`で起動します。

AI通知の接続先未設定・送信失敗・リレーの起動失敗・切断は、Poppy右下のエラー通知ウィンドウへ表示します。対象プロジェクトとターミナル、原因・復旧手順を表示し、✕で閉じるまで残ります。別の場所のクリックや時間経過では消えません。hook側の異常表示には、更新したPoppyとhookスクリプトの両方が必要です。`event_socket: null`の意味と復旧手順は[AI連携手順](integration/ai/README.md#通知エラーの表示と復旧)を参照してください。

Ctrl+Pのファイル検索は作業フォルダーの配下を対象に、ファイル名を優先して部分一致・あいまい一致で候補を表示します。未展開のフォルダーや未追跡ファイルも検索でき、同名のファイルは相対パスで見分けられます。起動時と作業フォルダーの切り替え時に、`.git`とリンク・ジャンクションを除く全ファイルの相対パスをバックグラウンドで取得します。入力時は取得済みの一覧だけを絞り込み、ディスク走査や入力後の待ち時間を挟みません。表示候補は上位100件までですが、一覧の取得件数に上限はありません。ファイルの追加・削除・名前変更を検知したときとF5で一覧を再取得し、更新中も前回の一覧で検索できます。

Ctrl+Fは未保存の編集を含む、開いている本文を直接検索します。Windows・WSLで同じ処理を使い、追加のファイル読み込みや通信は行いません。通常表示・読み取り専用表示と、差分の画面に表示される本文に対応します。文字列の部分一致で検索し、正規表現・単語境界・複数行の検索には対応していません。大文字小文字を区別しない設定で変換するのはASCII英字だけです。検索語はUTF-16で512コード単位までです。全一致位置を保存せず、件数と移動先を短い処理単位で計算します。描画では表示行の一致だけを再計算します。

Ctrl+Shift+Fは、選択中のプロジェクトの本文を既定で2並列・64 KiBずつ読み込んで検索します。WSLではLinuxヘルパー内で走査・検索し、一致した相対パス・行・列・抜粋だけをWindowsへ返します。未保存のファイルはエディター内の本文をコピーせずに検索し、保存済みの同じファイルとの重複を防ぎます。入力変更から150 ms後に検索を開始し、結果は順次表示します。検索語・設定の変更、Refresh／F5による再検索で結果を初期化します。編集・保存・ファイル通知では更新せず、プロジェクトやサイドバーを切り替えても保持します。切り替え・Escで進行中の検索を止めた場合も取得済みの結果は残ります。検索語・設定・結果・選択とスクロール位置はプロジェクトごとにSQLiteへ保存し、再起動時も再走査せず復元します。結果を開く時点で一致文字列を確認し、変わっていれば再検索を案内します。

既定では`.gitignore`・`.ignore`と通常の`.git/info/exclude`の規則を使います。隠しファイルも対象ですが、`.git`・`.hg`・`.svn`とリンク・ジャンクションは常に除きます。不正な文字コード・バイナリ、16 MiB超、100万行超のファイルは対象外です。結果は最大2,000件・構造体と文字列の概算2 MiB、抜粋は512バイト以内です。件数・容量の上限や読み込みエラーは検索欄の下に表示します。SQLiteへの本文保存や全文索引の構築は行いません。対応する除外規則、通信・メモリの上限、計測方法は[検索の実装と設計](docs/search.md)を参照してください。

アクティビティーバーのアイコンでサイドバーを切り替えます。表示中のEXPLORER・SEARCH・SOURCE CONTROLのアイコンをもう一度押すと、サイドバーを隠して編集領域を広げ、すべてのアイコンの選択を解除します。アイコンを押すと再表示し、幅・エクスプローラーの展開状態・検索結果は保持します。Ctrl+Shift+E / F / Gは対応するサイドバーを開いてフォーカスし、表示中でも隠しません。選択中のアイコンにはアクティビティーバーの外側の端に目印が付き、アイコンにマウスを重ねると名前とショートカットを表示します。`tests/folder_tests.cpp`に、表示切り替え・選択解除・幅の復元・非表示中のリサイズ・検索結果の保持を確認するGUIテストがあります。GUIテストの実行にはWindowsのデスクトップ環境が必要です。

エクスプローラーはWindows・WSLともフォルダーを先に表示し、名前を大文字小文字を区別しない自然順で並べます。数字を含む名前は`1_`、`2_`、`3_`、`4_`、`11_`の順になり、更新・名前変更・移動後も同じ順序を使います。WSLのファイル名とパスの大文字小文字は保持します。

エクスプローラーでは、Gitが無視するファイル・フォルダーの名前を薄い文字色で表示します。`.git`ディレクトリとその配下、Worktreeの`.git`ファイルも同じ薄い文字色で表示します。Windows・接続済みWSLの両方で、そのディレクトリのGitを使い、`.gitignore`の入れ子・例外指定や`.git/info/exclude`などを反映します。追跡済みファイルは無視対象にしません。無視されたフォルダーも展開・編集でき、ルールやGitの更新時に文字色を再判定します。Gitが利用できない場合やリポジトリの外では、`.git`とその配下を除き通常の文字色で表示します。自動監視できない変更はF5で更新してください。

無視判定は`tests/git_history_tests.cpp`で実際のGitを使い、入れ子のルール・リポジトリ、例外、追跡済みファイル、日本語・制御文字を含む名前、ルールの変更、問い合わせの分割・失敗を検証します。`tests/wsl_helper_tests.cpp`ではWSLヘルパー経由の判定を確認します。`tests/folder_tests.cpp`には文字色、無視フォルダー内のファイルの表示、ルール・インデックス変更後の更新、展開・選択の保持を確認するWindows用GUIテストがあります。GUIテストの実行にはWindows環境が必要です。

EXPLORERとSOURCE CONTROLのツリーは、フォルダー行の単クリックで展開・折りたたみできます。矢印・名前・行の余白は同じクリック処理を使い、連続クリックでも1クリックごとに開閉します。ドラッグやキャンセルでは開閉せず、行の右側の操作ボタンはそれぞれの操作を実行します。キーボードでは上下矢印で選択、右矢印で展開または子へ移動、左矢印で折りたたみまたは親へ移動します。Home / End / Page Up / Page Down、名前の先頭文字による検索、縦横スクロールにも対応します。フォルダーの読み込み中も折りたたみを受け付けます。アクティビティーボタンはクリック、Enter、Spaceで切り替えられ、Spaceはキーを離したときに確定します。

ファイルは複数のタブで開けます。タブの幅はファイル名の長さに合わせて変わります。タブはビューアーの幅に合わせて複数段に折り返し、ファイルを閉じたり幅を広げたりすると段数が減ります。高さに収まらない場合はコード表示領域を確保し、タブ領域の右下の`‹` / `›`で段単位に送れます。各タブのスクロール位置・選択範囲・通常表示／差分表示の状態を保持し、タブにマウスを重ねるとフルパスを表示します。通常表示と差分表示はそれぞれの表示位置を保持します。切り替え時にファイルや差分を読み直すため、非表示中の外部変更も反映します。別のフォルダーはプロジェクト一覧へ追加します。登録済みのフォルダーは同じプロジェクトを選び、ツリー・タブ・本文・入力先をメモリから表示します。切り替え時にSQLiteやGitの完了を待ちません。

Split／Inline、Source／Previewなどの切り替えボタンは、各グループで最後に表示しているタブの段の右端に配置します。タブの幅は段ごとに計算し、切り替えボタンと段送りボタンの幅は最終表示段だけに確保します。ボタンのない段では右端まで使い、末尾のタブとボタンが収まらない場合はタブを折り返します。固定タブの選択中や段送り後も最下段に配置し、1段だけの場合はシェル追加ボタンとも重ならないようにします。ドラッグの挿入位置も各段の表示幅に従います。`tests/tab_layout_tests.cpp`で、段別の折り返し、固定タブとの行の分離、段送りと選択タブの表示、リサイズ・タブを閉じた後の段数、狭い幅と表示倍率ごとの重なり防止を検証します。このレイアウト計算のテストはLinuxでも実行できます。`tests/folder_tests.cpp`にはHTMLの最下段の切り替えボタンとクリック領域を確認するWindows用GUIテストがあります。

新しく開いたファイル・画像・検索結果・Gitの個別差分・`All Changes`は、名前を斜体にした一時タブで表示します。一時タブは分割グループごとに1つで、次に別の対象を開くと置き換わります。残したいタブは、タブかエクスプローラー上のファイルをダブルクリックしてください。本文を編集した場合と`Pin tab`で固定した場合も、データを保護するため永続タブにします。Undoや固定解除で一時状態には戻りません。ドラッグして移動しても一時状態を保ち、移動先に一時タブがあれば置き換えます。既存の永続タブを開き直した場合は、そのタブと表示位置を使います。一時タブは再起動時に復元せず、従来から保存されているタブは永続タブとして復元します。

未保存の編集があるタブは、閉じるボタン／固定アイコンの左に`*`を表示します。通常表示・編集可能な差分表示ともに、長いタブ名が省略されても`*`は残ります。表示領域は未編集時から確保するため、編集・保存でタブの幅は変わりません。ファイル名は一時タブの斜体と永続タブの通常字体のうち広い方に合わせて最初から領域を確保し、編集やダブルクリックによる字体の切り替えで省略されることを防ぎます。

エディタータブの右クリック → `Close Others`は右クリックしたタブ以外を、`Close All`はすべてのタブを閉じます。分割時は右クリックしたグループだけが対象です。どちらも固定タブを残し、閉じられる対象がなければメニューを無効にします。未保存ファイルは保存・破棄・キャンセルを確認し、すべての確認が完了してからまとめて閉じます。途中でキャンセルした場合や保存に失敗した場合は対象タブをすべて開いたままにし、未保存本文を保持します。それまでに成功した保存は維持します。

Ctrl+Pや全文検索、個別のGit差分からファイルを開く、タブを切り替える、左右分割したエディター間でフォーカスを移すと、EXPLORERで対象ファイルの親フォルダーを展開し、その行を選択して表示領域の高さの中央へスクロールします。一覧の先頭・末尾付近ではスクロール可能な範囲に収めます。EXPLORERでファイルを直接クリック・ダブルクリックして開いた場合は、選択した行と現在のスクロール位置を維持します。既に開いているファイルをEXPLORERから選び直した場合も同じです。Windows・接続済みWSLに対応し、サイドバーの表示と入力フォーカスは維持します。ツリーで別の項目を操作すると読み込み待ちの自動選択を取り消します。`All Changes`、存在しないファイル、リンク先フォルダーの配下には自動選択を行いません。

`tests/folder_tests.cpp`に、未展開の階層・日本語パス、非表示のEXPLORER、タブの切り替えとクローズ、折りたたんだ親の再展開、中央へのスクロールと先頭・末尾での制限、EXPLORERから直接開いたときの位置保持とその後のCtrl+P・タブ切り替え、左右エディター間のフォーカス移動を確認するGUIテストがあります。実行にはWindowsのデスクトップ環境が必要です。

Gitはブランチ、変更数、未追跡ファイル数を表示します。SOURCE CONTROLは`Staged Changes`と`Changes`を分けて表示し、部分的にステージしたファイルは両方に表示します。前者はHEADとインデックス、後者はインデックスと作業ツリーの差分を開きます。各グループの右側の差分アイコン（`Open All Changes`）で、そのグループの差分を1つのタブにまとめて表示します。Changesの差分一覧には未追跡ファイルも追加ファイルとして含めます。単独の未追跡ファイルは通常のファイル表示を使います。

`Changes`で個別のテキストファイルを開くと、Inlineの現在の本文とSplitのAfter側を直接編集できます。変更の前後も編集できるよう全文を表示し、入力に合わせて差分を更新します。Ctrl+Sで作業ファイルへ保存し、ステージ済み内容は保持します。同じファイルの通常タブと本文・Undo履歴を共有し、タブ切り替え・F5・外部更新でも未保存本文を保持します。Before側、`Staged Changes`、コミット履歴、`All Changes`、削除済み・バイナリなど編集可能な本文を読み込めない比較は読み取り専用です。Windows・接続済みWSLで同じ操作を使います。

ステージ済み・コミット内のリネームはGitの類似度判定で検出し、移動先を1件の変更として表示します。個別ファイルと`Open All Changes`のどちらも移動元と比較し、名前だけの変更はリネームの案内、本文も変えた場合は変更箇所を表示します。Git設定でリネーム検出を無効にしていても、この表示では有効にします。未追跡の移動先をまだステージしていない場合は、Gitの状態に従い削除と未追跡ファイルとして表示します。

SOURCE CONTROLのファイル行にマウスを重ねると、`Changes`には＋アイコン（`Stage Changes`）、`Staged Changes`には−アイコン（`Unstage Changes`）を表示します。クリックするとファイル単位でステージ／解除し、一覧・変更件数・表示中の差分を更新します。未追跡ファイル、削除、リネームにも対応し、作業ツリーの内容は保持します。グループの差分アイコンもマウスを重ねたときに表示します。

`Changes`の見出しにマウスを重ねると、Discardの左に退避アイコン（`Stash Unstaged Changes`）を表示します。クリックすると、そのリポジトリの未ステージ変更と無視されていない未追跡ファイルをGitのStashへ保存し、作業ツリーをインデックスの内容へ戻します。部分ステージを含むステージ済み内容、HEAD、無視ファイル、エディターの未保存本文は保持します。見出しを折りたたんでいても使え、一覧・変更件数・表示中のファイルと差分を更新します。複数リポジトリではクリックした見出しのリポジトリだけを対象にし、Windows・接続済みWSLの両方に対応します。

Gitの`stash push --keep-index --include-untracked`を使うため、Stashには作業ツリーに加えてステージ済み内容のスナップショットも保存されます。名前は`Poppy: unstaged changes`で、ターミナルの`git stash list`等から確認・復元できます。競合がある場合と初回コミット前は退避せずエラーを表示します。ステージした新規ファイルを作業ツリーで削除した状態も、Gitがその削除を退避しないため停止します。先に該当ファイルのステージを解除してください。保存・作成・名前変更などが処理中の場合は完了後に実行してください。失敗時も一覧を更新し、Gitのエラーを表示します。サブモジュール内部の変更は退避しません。

`Staged Changes`の見出しにマウスを重ねると、−アイコンの左に退避アイコン（`Stash Staged Changes`）を表示します。クリックすると、そのリポジトリのステージ済み変更だけをGitのStash（`Poppy: staged changes`）へ保存し、インデックスと作業ツリーから取り除きます。未ステージ変更、未追跡・無視ファイル、HEAD、エディターの未保存本文を保持します。追加・削除・リネーム・バイナリに対応し、折りたたんだ見出しからも利用できます。複数リポジトリではクリックした見出しのリポジトリだけを対象にし、一覧・変更件数・表示中のファイルと差分を更新します。Windows・接続済みWSLの両方に対応します。

Git 2.35以降の`stash push --staged`を使います。部分ステージは変更箇所が離れていれば退避でき、ステージ済みと未ステージの変更が重なるなど、Gitが作業ツリーから取り除けない場合はエラーを表示します。この場合、Stashが作成済みのことがあるため、再実行前に`git stash list`と作業ツリー・インデックスを確認してください。競合は処理前に拒否し、初回コミット前や未対応のGitではエラーを表示します。失敗時も一覧を更新します。サブモジュール内部の変更は退避せず、保存・作成・名前変更などとの同時実行も行いません。

Git一覧は初期状態では`Tree`表示です。`Tree` / `List`で作業中とコミット内の変更ファイルの表示を切り替えられます。相対パスはGitリポジトリのルートを基準に表示します。Treeのフォルダーは行の単クリック、左右矢印・Enter・Spaceで展開・折りたたみでき、更新や表示の切り替えでも折りたたみ状態を保持します。表示形式はプロジェクトごとに保存し、再起動後も復元します。エクスプローラーとGit一覧の状態は名前の色で示します。追加・未追跡は緑、削除・競合は赤、変更・リネームなどは黄です。選択中も状態の色を保持します。削除済みファイルも差分を開けます。コミット操作はターミナルで行います。

アクティビティーバーの`Source Control`またはCtrl+Shift+Gで`SOURCE CONTROL`を開きます。ローカル・リモート追跡ブランチを表示し、各リポジトリの直下に`Compare…`を1つ置き、その後にブランチを並べます。リポジトリが1つの場合は最上位に表示します。現在のブランチ内では`Staged Changes`、`Changes`、最新コミットの順に並べます。変更がない場合や初回コミット前も両グループを表示します。従来のCtrl+Shift+Bと保存済みのBRANCHページはSOURCE CONTROLへ引き継ぎます。ブランチを開くと新しい順に50件のコミットを表示します。51件目の行の`Load 50 more commits…`をクリックすると、さらに50件ずつ追加します。コミットを開くと変更ファイルを選択中のTree／List形式で表示し、ファイルを選ぶとそのコミット時点の差分を開きます。コミット行にマウスを重ねると右側に差分アイコンが現れ、クリックすると全変更を1つの差分タブに表示します。アイコンのツールチップは`Open All Changes`です。`Open All Changes`・ステージ・解除・破棄・退避などの操作アイコンには通常の背景色を付けず、アイコン自体にマウスを重ねたときだけ薄い白色（不透明度10%）の背景を重ねます。初回コミットは追加ファイルとして、マージコミットは最初の親との差分として表示します。現在のブランチを切り替えずに履歴を閲覧でき、detached HEADも表示します。コミットとSOURCE CONTROLのグループを選んでF4を押しても`Open All Changes`を実行できます。

Poppyのウィンドウを閉じると、暗いテーマと緑のアクセントを使った`Closing Poppy`ダイアログを表示します。保存・プロジェクトとターミナルの停止・リソース解放の進捗、対象プロジェクトと端末名、Docker／WSL／Windowsプロセスの停止待ち、経過秒数を表示し、完了すると自動的に閉じます。表示中はPoppyのウィンドウ全体を暗くし、操作を無効にします。停止待ちの間も進捗のアニメーションは更新します。未保存ファイルの確認をキャンセルした場合は終了処理を始めません。

Editor上部のファイル名・文字コード・Modified等のヘッダーは表示しません。ステータスバーはPROJECTS領域も含めたウィンドウ下端の全幅に表示し、選択中のプロジェクトに追従します。右端に、選択中のエディターの文字コード（`UTF-8`、`UTF-16 LE`、`UTF-16 BE`）と改行コード（`CRLF` / `LF`）を表示します。改行コードは編集時と同じく最初の改行で判定し、改行のないファイルは`LF`と表示します。左右分割では最後に選択したエディターに追従し、編集・Undo / Redo・タブの切り替え・外部更新後にも再判定します。Git差分・読み込み中・エラー表示では文字コードと改行コードを隠し、画像では画素数を表示します。

WSL・WindowsのファイルやGit差分を開くとき、`Loading…`などの読み込みメッセージは1秒以上読み込みが続いた場合だけ表示します。待機中のステータスバーにはファイル名を表示し、読み込み完了・エラー・タブの切り替えやクローズで、以前のメッセージの表示予約を取り消します。Gitリポジトリの検出から差分の取得へ進む間は、同じファイルの待ち時間を引き継ぎます。

`tests/render_tests.cpp`に、読み込み表示の待ち時間、タブ切り替え時の古いタイマー、Gitの読み込み段階の切り替え、本文・差分・画像・エラー・クローズによる表示予約の取り消しを確認するWindows用テストがあります。実行にはWindows環境が必要です。

ステータスバーには`Tree 1,234/50,000`のように、保持しているエクスプローラー項目数と上限を表示します。WSLプロジェクトでは`Watch 1,234/262,144`（接続で共有するディレクトリ監視数）と`Files 12,345/400,000`（Ctrl+P用のファイル一覧）も表示します。Watchの上限はWSLヘルパー起動時に読み取った`fs.inotify.max_user_watches`の半分で、Linux側が524,288件なら262,144件です。設定変更後はPoppyを終了して起動し直してください。Linux側の値を取得できない場合は65,536件を使います。マウスを重ねると、それぞれの対象範囲、上限、制限された場合の動作を確認できます。Filesの説明には索引の保持メモリの概算と256 MiBの予算も表示します。監視の不足や不完全な一覧には黄色と`!`を使い、幅が足りない項目は`Limits`の説明へまとめます。切断中や初回取得前はWatchの使用数・上限をともに`—`で示します。

SOURCE CONTROLのコミット行にマウスを約0.5秒重ねると、件名と本文を含むコミットメッセージを独自のポップアップで表示します。長文は折り返してスクロールでき、ポップアップへマウスを移しても表示を保ちます。本文をドラッグで選択してCtrl+C、右クリックの`Copy`、または上部の`Copy all`でコピーできます。Ctrl+Aで全文選択も可能です。改行・空白・日本語を保持し、表示時にツリーの選択や入力先を変更しません。Esc、マウスが行とポップアップの外へ移動したとき、一覧のスクロール・更新・非表示で閉じます。右端の操作アイコンには従来のツールチップを表示します。Windows・接続済みWSLの履歴で利用できます。

`tests/git_history_tests.cpp`で本文と空白を含むGit出力の解析・ページ境界を検証します。`tests/render_tests.cpp`には100% / 150% / 200%のDPIで、ホバー時の入力先保持、ポップアップへの移動、範囲選択・全文コピー、長文のスクロール、Esc・一覧更新時の終了を確認するWindows用GUIテストがあります。GUIテストの実行にはWindowsのデスクトップ環境が必要です。

## 作業領域と前回状態の復元

保存先は `%APPDATA%\yumayo\Poppy` です。`APPDATA` が未設定の環境ではWindowsのRoaming AppDataフォルダーを使います。

```text
%APPDATA%\yumayo\Poppy\
  storage.sql
  projects\
    -d-repository-yumayo-poppyworktrees-poppydirect2d\
      storage.sql
```

全体の `storage.sql` はSQLite3のデータベースで、前回のプロジェクト、ウィンドウの位置・大きさ・最大化状態、プロジェクトと保存先の対応を管理します。プロジェクトごとの `storage.sql` には共通の差分表示形式（Split／Inline）、タブの順序と選択、各タブの表示位置・選択範囲・通常／差分表示、エクスプローラーの展開と選択、サイドバーの種類と幅、下段の表示と、入れ子の分割方向・比率、Editor／Terminalの配置・混在順序・各領域の選択を保存します。開いている一覧と選択・一覧幅、各ペインの選択とスクロール、Gitの折りたたみ、ターミナルID・名前・順序・起動フォルダーも保存します。操作後650 msの待ち合わせを経て、専用ワーカーがSQLite接続を所有して保存します。プロジェクトの切り替えは保存を待ちません。終了時は非表示プロジェクトも保存します。

プロジェクトの保存先名は絶対パスを小文字にして区切り文字などをハイフンへ置き換えます。同じ名前になる別のパスにはハッシュの接尾辞を付け、既存の保存先と分けます。長い名前は短縮してハッシュを付けます。再起動時は通常表示のファイルが削除されていればそのタブを除外し、削除ファイルの差分タブは復元します。通常終了後の起動ではターミナルの構成だけを復元し、次に操作したときにシェルを新しく起動します。更新のRestartでは保存したホストIDで再接続し、同じ実行プロセスと画面・出力履歴を引き継ぎます。

保存はトランザクションで行い、プロジェクトの保存中に失敗した場合は前回の状態を残します。読み込み・保存に失敗した場合はメッセージを表示します。より新しいバージョンの保存形式は上書きしません。

保存先の命名規則、SQLiteのテーブルとカラム、保存・復元の流れは [DATASTRUCTURE.md](DATASTRUCTURE.md) にまとめています。

## メモリを抑える構成

- ファイルツリーは`.git`を含めて展開した階層だけ列挙し、折りたたんだ配下のノードを解放します。ディレクトリのリンク・ジャンクションは再帰展開しません。
- 各プロジェクトで最後に表示した本文を保持し、全体64 MiBを超えた場合は古い非表示プロジェクトの本文から解放します。解放後はタブと位置を先に表示し、本文を非同期で読み直します。各プロジェクト内では表示中のファイル本文だけを保持します。非表示タブにはファイルパス・表示位置・選択範囲・差分表示の状態だけを残し、切り替え時に本文を読み直します。本文のUTF-8スナップショットと行頭位置・行ごとの字句状態を保持し、表示行のトークンと描画用文字列をその場で作ります。Ctrl+P用に全ファイルの相対パスと検索用の正規化済みパスを保持しますが、非表示ファイルの本文や全行の描画キャッシュは保持しません。
- ディスクI/OとGitは別のワーカーで処理し、UIスレッドでファイル走査やGitの終了待ちを行いません。古い読み込み結果を表示しないよう世代と要求番号を確認します。
- シェルは操作時に起動します。ターミナルは固定セルの画面と上限付き履歴を持ち、外部ターミナルアプリを埋め込む構成にはしません。
- 大量のターミナル出力は8 KiB単位で全セッションを順番に処理し、時間が残っていれば同じ回で続きを解析します。1回の通知での解析時間を約5 ms以内に制限し、残りがあれば次のメッセージで待機時間を挟まず処理します。入力・描画・タイマーのメッセージを優先し、大量出力中もUI操作を処理します。表示が追いつかない場合は出力側を待機させ、メモリ増加とUIの占有を抑えます。
- ターミナルの通常出力・入力の応答・リサイズ・手動スクロールは、固定間隔や出力の静止を待たず、その場で表示と描画を更新します。同期更新の指定中は終了指定まで確定済み画面を保持し、終了指定が欠けた場合は1秒で解除します。タイマーはこの解除期限にだけ設定し、同期更新の終了指定や通常出力の到着は受信通知で即座に処理します。同期更新中に要求したスクロール位置は画面の確定時に反映します。再表示・フォーカス変更やコピーにも表示用の画面を使います。
- ディレクトリー変更の完了イベントは80 msの共有タイマーで確認し、プロジェクト数をUIの待機ハンドル数に直結させません。Gitの常時取得は行わず、変更通知、選択時、再アクティブ時、F5で再検証します。

| 項目 | 初期上限 |
| --- | --- |
| ファイル | 読み込み時・UTF-8変換後ともに16 MiB / 1,000,000行 |
| 長い行の表示 | 先頭8,192桁まで。コピー対象には全文が残る |
| ファイルツリー | 1フォルダー10,000件 / 全体50,000ノード |
| Git変更ファイル一覧 / 状態の色分け | 50,000ファイル / 親ディレクトリを含め50,000パス |
| GitのTree表示の親フォルダー | 最大50,000ノード。上限を超える階層は残りの相対パスをファイル名として表示する |
| Gitコマンドの出力 | 1回4 MiB / 差分は1,000,000行まで |
| ターミナル画面 | ホストとUIそれぞれに最大500列 × 200行 × 通常・代替の2画面 |
| ターミナル表示用画面 | 最大500列 × 200行の1画面。履歴は複製しない |
| ターミナル履歴 | ホストとUIそれぞれ最大1,000行、かつ131,072セル。各セル領域は約2 MiB以内 |
| ターミナル受信待ち | ホストの差分は256 KiB。超過時は画面スナップショットへ切り替え、ConPTYの読み取りを続ける。UIは512 KiBで受信を待機し、スナップショット1件分を追加許容 |
| ターミナル送信待ち | 1 MiB。超過する入力は受け付けない |

これらはアプリ全体のメモリ上限ではありません。読み込み中の旧・新ファイル、UTF-16変換、コピー、Gitの結果入れ替えなどで一時的な追加領域を使用します。Windowsの共有DLL、ツリーの階層・表示位置とラベル幅のキャッシュ、Direct2Dの描画先やGPUドライバーの領域も必要です。PowerShell・AI CLI・Gitは別プロセスでメモリを使います。

## 初版の表示範囲

ファイル表示はUTF-8、BOM付きUTF-16 LE / BEに対応します。NULを含むバイナリーはテキスト表示の対象外です。Shift_JISなどの文字コードの自動判定・変換は行いません。簡易シンタックスハイライトはC/C++、C#、JavaScript/TypeScript、Rust、Go、JavaなどのC系構文、Python、シェル、JSON、TOML/YAML/INI、Git差分を対象とします。言語の完全な構文解析は行いません。

UTF-8として読むファイルに不正なバイトが混在している場合は、1バイトずつ代替文字`�`（U+FFFD）へ置き換えて表示します。PHPのProtocolBuffers生成ファイルなどでも前後の本文・改行を保持し、BOMの有無にかかわらず読み込めます。表示だけでは元ファイルを変更せず、編集後に保存すると代替文字を含む本文を書き込みます。置換後の本文にも16 MiBの上限を適用します。

PNG・JPEG（`.jpg` / `.jpeg`）・BMP・GIF・TIFF（`.tif` / `.tiff`）・ICOは、EXPLORERやCtrl+Pから通常のタブで画像を表示します。Windows・接続済みWSLの両方に対応し、透過部分には市松模様、下部ステータスバーには元の画素数を表示します。縦横比を保って領域に収め、大きい画像は縮小、小さい画像は元の画素数で表示します。リサイズ・左右分割・DPI変更に追従し、タブ切り替え・外部更新・F5で再読み込みます。表示は読み取り専用で、GIF・TIFF・ICOは最初のフレームを表示します。Git差分は従来どおりバイナリー変更の案内です。ファイルは16 MiB、展開後の画素は64 MiB、縦横それぞれ16,384画素までとし、破損・未対応・上限超過の場合はエラーを表示します。読み込みと画像の展開はバックグラウンドで行います。

ターミナルはConPTYのUTF-8出力を受け取り、基本的なカーソル移動、行・文字の挿入と削除、スクロール領域、代替画面、16/256/true color、bracketed paste、カーソル・背景色の照会、同期更新（DEC private mode 2026）の開始・終了と状態照会に対応する小さなVT実装です。日本語などの全角文字とIMEの確定文字列を扱うコードを含みます。

Windows Terminal相当の互換性はまだありません。結合文字・ZWJ絵文字の合成、文字装飾の完全再現、マウスプロトコル、画像、Kittyキーボードプロトコル、履歴の折り返し再計算は未対応です。使うAI CLIで表示と操作を確認する必要があります。

## Editorでの修正

Editorの本文末尾には表示領域に応じた余白があり、短いファイルでも最終表示行が本文領域の上端に来るまでスクロールできます。折り返し・リサイズ・DPI変更・検索欄の表示に追従し、Git差分のInline／Split表示にも対応します。All Changesでは固定ファイル名の直下まで最終行を移動できます。余白はファイルの本文・行番号・コピー対象には含めません。コミットメッセージのポップアップには追加しません。

スクロール範囲とGit変更マーカーの位置は`tests/editor_tests.cpp`で検証します。`tests/render_tests.cpp`には最終行までのスクロール・表示位置の復元、折り返し・DPI・高さ・検索欄・差分表示ごとの範囲を確認するWindows用回帰テストがあります。GUIテストの実行にはWindowsのデスクトップ環境が必要です。

表示中のテキストファイルで一番下までスクロールしていると、外部から追記・更新された際に再読み込み後の末尾へ自動で追従します（tail）。上へスクロールするとその位置を保ち、最下部へ戻ると追従を再開します。画面内に収まる短いファイルや、改行なしで伸びる折り返し行にも対応します。Windows・接続済みWSLの既存のファイル監視を使い、未保存の編集がある場合は本文を保持します。

`tests/render_tests.cpp`に、折り返し・DPIごとの末尾追従、停止・再開、共有本文を表示する各ペインの位置、選択・水平位置の保持、切り詰めと再成長、通常の編集更新・Git差分との独立性を確認する回帰テストがあります。`tests/folder_tests.cpp`では実ファイルへの追記・切り詰めによる自動更新と未保存本文の保持を検証します。これらのGUIテストの実行にはWindowsのデスクトップ環境が必要です。

通常の本文表示は、Editorの表示幅に合わせて長い行を折り返します。読み取り専用表示でも同じ動作です。折り返しによってファイルへ改行を追加することはありません。リサイズ・左右分割・DPI変更時に表示幅を再計算し、カーソル移動・選択・検索も折り返した表示行に対応します。行番号は元の行の先頭だけに表示します。折り返し行の途中の表示位置も、タブ切り替え・再起動時に復元します。

Git差分のInline／Split表示も同じフラグで折り返します。Splitでは各ペインの幅で折り返し、左右のうち長い側に高さを合わせて次の行の位置をそろえます。選択・コピー・検索に対応し、Inline／Splitの切り替えやリサイズ後も元の本文位置を基準に表示位置を復元します。

将来の設定画面から切り替えられるよう、`Viewer::setWordWrap(bool)`と`Viewer::wordWrap()`を用意しています。既定値は`true`で、`false`にすると横スクロールへ戻ります。設定画面・設定の保存はまだ追加していません。

通常のファイル表示とChangesの個別テキストファイルの現在の本文で文字入力、日本語IME、選択置換、Enter、Tab、Backspace / Delete、矢印・Home / End・Page Up / Down（Shiftで選択、Ctrl+Home / Endで先頭・末尾）が使えます。Ctrl+C / X / V、Ctrl+A、Ctrl+Z（Undo）、Ctrl+Y / Ctrl+Shift+Z（Redo）、Ctrl+S（保存）と右クリックメニューに対応します。

中ボタンを押しながら本文をドラッグすると、複数行の同じ列範囲を矩形選択できます。折り返した表示行ごとに選択し、上下端の外へドラッグすると自動スクロールします。横幅なしで上下にドラッグすると各行にカーソルを置き、文字入力・IMEの確定・Tab・Enter・Backspace / Deleteをまとめて適用できます。短い行の末尾より先も選べ、入力時に必要な空白を補います。日本語・絵文字・タブは文字の途中で分割しません。

Ctrl+C / Xでは各行の選択部分を改行でつなぎ、Ctrl+Vでは貼り付ける行数と選択行数が一致すると1行ずつ割り当てます。それ以外は各カーソルへ同じ本文を挿入します。1回の入力・削除・貼り付けは1回のUndoで戻せます。左クリック・矢印キー・Escで通常のカーソルに戻り、タブ・表示形式の切り替え、リサイズ、外部更新では矩形選択を解除します。読み取り専用表示と差分のBefore側では選択・コピーを利用できます。

`tests/editor_tests.cpp`で矩形の文字境界、短い行・空行、コピー、複数行の編集とUndo／Redo、貼り付けの振り分け、上限超過時の一括拒否を検証します。`tests/render_tests.cpp`には中ボタンのドラッグと解放、左右・上下の逆方向、DPI・折り返し、Inline／Split差分、読み取り専用表示、通常選択への復帰と自動スクロールを確認するWindows用テストがあります。GUIテストの実行にはWindowsのデスクトップ環境が必要です。

Ctrl+← / →で単語単位に移動し、Ctrl+Shift+← / →で選択範囲を伸縮できます。英数字とアンダースコアは1つの単語として扱い、日本語などの連続した文字にも対応します。記号の連続は単語と分け、空白・タブ・改行は読み飛ばします。Shiftなしで選択中に左右へ移動すると、その方向の選択端へ移動して選択を解除します。

Ctrl+BackspaceはCtrl+←の移動先までを削除します。選択中は選択範囲だけを削除し、1回のUndo / Redoで戻せます。ChangesのInline／Split表示の編集可能な本文でも利用できます。ターミナルではCtrl+Wを送信し、PowerShell・Git Bash・WSLのシェル側の単語削除に従います。

本文の文字をダブルクリックすると、その文字を含む単語を選択します。単語の区切りはCtrl+← / →と共通で、記号や空白はそれぞれの連続範囲を選択します。改行を含めず、折り返された単語も全体を選択します。読み取り専用表示でも利用できます。

未選択時のCtrl+Xは、カーソルのある行を改行ごと切り取ります。最終行に改行がなければ直前の改行も削除し、クリップボードにはその行の本文だけを入れます。選択中は選択範囲だけを切り取ります。Shift+Alt+↑ / ↓で現在行を上下の行と入れ替え、複数行の選択中は対象の行群をまとめて移動します。選択の末端が次の行の先頭にある場合、その行は含めません。画面で折り返した長い行も元の1行として扱い、カーソルの行内位置・選択方向・既存の改行形式を保ちます。先頭での上移動・末尾での下移動は何もしません。切り取り・入れ替えはそれぞれ1回のUndo / Redoで戻せます。

`tests/editor_tests.cpp`で行の切り取り範囲、空行・末尾改行の有無、LF / CRLFの混在、日本語・絵文字、選択方向、Undo / Redoと文字コードの保持を検証します。`tests/render_tests.cpp`にはCtrl+Xのクリップボード内容、Shift+Alt+↑ / ↓のキー入力、折り返し・DPI変更時の選択とカーソル位置、読み取り専用表示を確認するWindows用テストがあります。GUIテストの実行にはWindows環境が必要です。

未保存タブには `*` と `Modified` を表示します。タブ・プロジェクト切り替え、F5、AIによるファイル更新でも未保存本文を保持し、タブ・プロジェクト・アプリを閉じるときは保存・破棄・キャンセルを選択できます。未保存本文はメモリ内だけで保持し、異常終了からの復元は行いません。保存はUTF-8（BOM有無）、BOM付きUTF-16 LE / BEと既存改行を維持し、新規改行・貼り付けは最初の改行形式に合わせます。外部更新後の保存は拒否して編集を保持するため、必要な修正をコピーしてタブを閉じ、最新ファイルを開いて反映してください。一時ファイルを書き終えてから元ファイルを置換します。

ファイルは16 MiB・100万行未満、Undoは直近1,000操作・約16 MiBを目安に制限します。簡単な修正向けに各操作後に行索引とハイライト状態を更新します。未保存ファイルはメモリ回収の対象外です。

エディターとターミナルのIME変換中の文字は、本文と同じDirectWriteの描画処理で、全角を2セル・半角を1セルに配置します。日本語の代替フォントがプロポーショナルでも文字の開始位置が揃います。IMEに渡す`LOGFONT.lfWidth`は平均文字幅の指定であり、フォント名・サイズと合わせるだけでは各文字の幅を固定できないため、標準の変換文字列ウィンドウを抑止してアプリ側で描画します。変換対象の下線・背景と変換中のカーソルを表示し、右端での折り返しとDPI変更に対応します。未確定の文字は本文や端末に送らず、確定文字列を受け取ってから反映します。候補一覧は使用するIMEが表示し、候補位置と非表示のWindowsキャレットは変換中のカーソルに追従します。候補一覧は入力行の下、下に収まらない場合は上に表示するよう、モニターの作業領域の横幅全体にわたる入力行を`CFS_EXCLUDE`で除外します。検索欄・ファイル／プロジェクト検索・名前変更欄にも同じ指定を使います。バックグラウンド端末の出力や検索欄のレイアウト更新では、フォーカスのある入力先の位置・フォントを上書きしません。`tests/editor_tests.cpp`では、半角・全角・サロゲートペアのセル位置、UTF-16のカーソル・属性位置、折り返しをLinuxでも検証します。`tests/render_tests.cpp`には、変換中と端末本文の画素比較、下線、候補位置、確定前の本文保持、共有入力コンテキストと100% / 125% / 150% / 200%表示倍率の回帰テストがあります。描画テストの実行と実際の日本語IMEでの表示確認にはWindows環境が必要です。

ターミナルでは、IME変換中の文字をカーソル位置へ表示上だけ挿入し、後続文字をそのセル幅だけ後ろへずらします。かなから漢字への変換や候補変更で長さが変わるたびに、元の端末表示から配置を作り直します。全角文字・絵文字を分割せず、後続文字の色を保ち、自動折り返しで続く行も配置し直します。未確定文字はシェル・CLIへ送らず、キャンセルやフォーカス移動で元の表示に戻し、確定後は端末から届く出力に引き継ぎます。マウスで端末の選択を始めると変換をキャンセルします。表示範囲は自動折り返しでつながる行と直後の空行までとし、独立した出力行や検出できる縦罫線の枠を移動しません。ハイフンや罫線文字だけで描かれた横の区切り線も境界とし、端末幅いっぱいの描画で折り返し情報が付いていても変換表示に巻き込みません。収まらない場合は、その範囲内で変換中のカーソルが見える行を表示します。任意のCLIの入力欄を意味的に識別する方式ではありません。`tests/core_tests.cpp`で変換時の伸縮、確定・取消し、折り返し、端末内容の保持と枠の境界を検証し、`tests/render_tests.cpp`に各DPIで確定後の挿入表示と画素を比較するWindows用テストを含みます。

Claude Codeなどが応答中に画面を描き直しても、IME変換中は変換開始時のセルを入力位置として保持します。端末の出力は更新し続け、描画用カーソルが先頭や末尾へ移動しても未確定文字・Windowsキャレット・候補一覧はその位置を追いません。確定・キャンセル・フォーカス移動で保持を解除し、次の変換では改めて入力位置を取得します。確定直後に次の変換を始めた場合は、端末から確定文字と更新後の入力カーソルが届いてから位置を取得し直し、古い位置に固定されることを防ぎます。通常文字を挟んだ入力、分割された出力、折り返しと入力欄の上下移動にも対応し、入力待ちのためにキー操作を止めることはありません。リサイズ・画面バッファ切替・端末リセットでは古い座標を破棄します。`tests/core_tests.cpp`で出力中の変換位置・連続確定・候補変更・折り返し・横罫線の境界・同期出力を検証し、`tests/render_tests.cpp`にはConPTY経由で再描画を行い、フォーカス・Windowsキャレット・候補位置と変換終了後の追従を確認するWindows用テストを含みます。

Claude Codeが通常の端末カーソルを隠して入力文字を反転表示する場合は、横罫線で囲まれたプロンプト内の反転1文字をIMEの入力位置として使います。全角文字や絵文字ではその先頭セルへ挿入し、変換表示では元の反転を解除して後続文字をずらします。確定文字の反映もこの入力位置で確認するため、端末の描画カーソルがフッターに残ったままでも次の変換位置を更新できます。通常のカーソルが表示されている場合はその位置を使い、複数文字の反転や候補が複数ある表示からは位置を推測しません。コアテストには入力欄外への表示・全角1文字分のずれ・連続確定・色・複数行・ホストへの再接続の回帰テストを、Windows用テストにはConPTY経由の反転カーソルとWindowsキャレット・候補位置の確認を含みます。実際のClaude Codeと日本語IMEの組み合わせはWindows実機で確認が必要です。

EXPLORERの名前変更・新規ファイル／フォルダー作成、全文検索、ファイル内検索、ファイル検索、最近使ったプロジェクトの検索、Terminalタブの名前変更、EXPLORER／Git一覧の文字入力による項目選択も、共通のIME変換状態管理・候補位置の設定を使います。これらの入力欄ではSegoe UIのプロポーショナルフォントを維持し、入力済みの文字列・変換中の文字列・後続の文字列を1つのDirectWriteレイアウトで整形します。同じレイアウトから文字位置、変換対象の背景・下線、選択範囲、マウスの入力位置、非表示のWindowsキャレットと候補位置を求めます。長い変換中の入力はカーソル位置に合わせて横スクロールし、確定するまで検索や名前変更へ反映しません。`tests/render_tests.cpp`にはプロポーショナル文字の画素比較、UTF-16のカーソル位置、結合文字・絵文字のヒットテスト、変換キャンセルとフォーカス移動、DPIごとのUIフォントと共有入力コンテキストの回帰テストもあります。

## Editor / Terminalのドッキング

初めてプロジェクトを開くときは、Terminalだけを最上段のタブグループに表示します。

マウスの戻るボタン（XBUTTON1）／進むボタン（XBUTTON2）で、アクティブにしたEditorタブとTerminalの履歴を移動できます。プロジェクトと分割グループをまたいで切り替え、入力フォーカスも復元します。非表示の下段にあるタブへ戻る場合は下段を表示します。戻った後に別のタブやTerminalを選ぶと、進む履歴を破棄します。同じ対象の連続選択は追加しません。

履歴はPoppyを終了するまで直近1,000件を保持します。置き換えられた一時タブも表示位置を保持して再表示でき、履歴のために本文やUndoを複製しません。明示的に閉じたタブ・Terminal・プロジェクトはスキップします。`tests/navigation_history_tests.cpp`で順序・分岐・上限・解放・一時タブの情報を、`tests/folder_tests.cpp`でマウスとアプリコマンド、表示位置・フォーカス・左右分割・Terminal・プロジェクトをまたぐ移動を検証します。後者の実行にはWindowsのデスクトップ環境が必要です。

EditorとTerminalは共通のタブグループを使います。どちらのタブも、別の領域のタブ見出しや本文中央へドラッグするとそのグループへ移動できます。同じグループ内でファイルとシェルを切り替えられます。本文の左・右・上・下の端へドロップすると、その方向へ新しいグループを作ります。右下の領域をさらに上下へ分けるなど、既存の領域を繰り返し分割でき、4領域に固定されません。移動先の判定とプレビューは、折り返したタブ見出しも除く本文領域で計算します。同じ領域の中央へ戻す場合も「Move tab here」を表示し、配置とタブ順序を保ちます。ドラッグ中のタブはつかんだ位置を保ってマウスに追従し、ウィンドウの端や外側でも止まりません。色付きの移動先を確認してマウスを離してください。Esc、キャプチャ喪失、領域外へのドロップでキャンセルします。

EXPLORER・Ctrl+P・全文検索・SOURCE CONTROLから新しく開くファイルや差分は、下段を操作していても最上段のタブグループに追加します。最上段が左右に分かれている場合は、その段でフォーカス中のファイル領域を使い、下段から開く場合は最上段の左端のファイル領域を使います。Dockが1つだけの場合は、ターミナルを表示中でもそのDockでファイルを開きます。複数のDockがある場合はターミナルを表示中の領域を追加先から除き、最上段にターミナルしかなければ、その上にファイル用の領域を作ります。一時タブもその追加先で置き換えます。既に開いているタブは現在の配置で選択し、手動で下段へ移動したファイルもその場所を維持します。

各境界をドラッグして幅・高さを調整できます。最後のタブを移動・クローズした空の領域は、隣の領域へ統合します。ターミナルタブを表示している領域だけに`+`と下矢印を表示し、シェルの追加やシェル・WSLのAIの選択ができます。ファイルを表示している領域では両ボタンを非表示にし、その幅もタブに使います。同じ領域でファイルとターミナルを切り替えると、ボタンの表示も切り替わります。HTMLプレビューや差分表示の切り替えは、選択したタブの右側に表示します。移動しても未保存本文・Undo・表示位置と、実行中のConPTYセッションを保持します。

Ctrl+J / Ctrl+`は、最上位の上下分割の下側を非表示にし、もう一度押すと分割構造ごと復元します。ターミナル入力中のCtrl+JはシェルやCLIへ渡し、下段の表示切り替えにはCtrl+`を使います。左右の列が先に分かれている場合は、各列の最上位の上下分割に適用します。下段にEditorを置いた場合も同じ動作で、上段のTerminalは表示を続けます。隠した領域のタブやプロセスは閉じません。配置、混在タブの順序、選択、分割比率、下段の表示状態をプロジェクト単位で保存します。従来のEditor／Terminalの左右分割を保存している場合も、新しいレイアウトへ移行します。

`tests/dock_layout_tests.cpp`で6領域以上の入れ子の配置、上下左右のドロップ判定、境界の変更、小さいウィンドウ、空領域の統合、下段の非表示・復元、不正な保存データと混在タブの保存を検証します。`tests/storage_tests.cpp`では、深いグループIDと分割状態のSQLite保存・復元を確認します。Windows用の`poppy_dock_ui_tests`はTerminalを上段へ、Editorを下段へ移動し、6領域への分割、Ctrl+J、未保存本文と実行中のシェルの保持、再起動後の配置を検証します。GUI・ConPTYテストの実行にはWindowsのデスクトップ環境が必要です。

WindowsのFile Explorerから、開いているプロジェクトのタブ領域またはエディター本文へファイルをドラッグ＆ドロップすると、元の場所のファイルをタブで開きます。プロジェクト外のCSVやテキストも、プロジェクトへコピーせずに確認・編集でき、Ctrl+Sで元のファイルへ保存できます。WSLプロジェクトを開いているときもWindows側のファイルを開けます。複数ファイルはそれぞれ通常のタブとして残り、既に開いているファイルは現在のタブを選択します。追加先はドロップした領域です。外部ファイルの再読み込みにはF5を使います。フォルダーはタブとして開きません。

本文の文字・行番号・余白や、ファイルを選択していないEditorの空白部分にもドロップできます。Editorを分割している場合は、それぞれの本文領域を追加先にできます。

`tests/session_tests.cpp`で、複数ファイルの追加、既存タブ・未保存本文・表示位置の保持、保存と復元、WindowsとWSLのパスの区別を検証します。`tests/render_tests.cpp`には、空のEditor・テキスト・差分・画像への切り替えと分割Editorで、本文のドロップ先の登録・解除を確認するWindows用テストがあります。

## エクスプローラーのファイル操作

Ctrl＋クリックでファイルやフォルダーの選択を追加・解除し、Shift＋クリックで最後の選択位置から表示中の行を範囲選択します。Ctrl＋Shift＋クリックで既存の選択へ範囲を追加できます。Shift＋↑↓／Home／End／Page Up／Page Downでも範囲選択でき、Ctrl+Aで表示中の項目をすべて選択します（プロジェクトのルートは除きます）。通常のクリックで単一選択に戻ります。選択済みの行を右クリックしても複数選択を保持し、名前変更は単一選択時に使えます。

Ctrl+C／Ctrl+X、または右クリックの`Copy`／`Cut`で選択項目をコピー・切り取り、移動先を選んでCtrl+V／`Paste`で貼り付けます。ファイル選択時はその親、空白部分の右クリックではプロジェクトのルートが貼り付け先です。フォルダーは中身もコピーします。親と子を一緒に選択した場合、親だけを操作します。同じフォルダーへのコピーには` - Copy`（必要なら連番）を付け、ファイルの拡張子を保ちます。別フォルダーの同名項目は上書きせずエラーにします。ディスク上の内容をコピーするため、未保存の編集は先に保存してください。

Windows・接続済みWSLのファイル／フォルダーを、File Explorerとのファイルクリップボードで受け渡しできます。WSLは`\\wsl.localhost`／`\\wsl$`のパスを使い、File Explorerから受け取った同じディストリビューションの項目は、貼り付け先プロジェクトの接続ユーザーの権限でコピーします。Poppy間では同じディストリビューション・接続ユーザーでコピー・切り取り・貼り付けができます。Windowsのファイル／フォルダーはWSLへもコピーできます。接続先の`wslpath`でWindowsパスを変換し、接続ユーザーの権限でコピーするため、そのWSLからアクセスできるWindowsドライブが必要です。WindowsからWSLへの切り取り、WSLからWindows、異なるWSL接続の間のPoppyへの貼り付けには対応していません。WSLのシンボリックリンクはリンクとしてコピーし、Windowsのリンク／ジャンクションを含むコピーはエラーにします。名前にバックスラッシュを含むWSL項目は、名前を保持できるPoppy間のクリップボードだけで扱います。File Explorerへ渡したWSL項目はWindows側のWSL共有のアクセス権を使います。

WindowsのFile ExplorerからPoppyのEXPLORERへファイル／フォルダーをドラッグ＆ドロップすると、強調表示したフォルダーへコピーします。ファイルの行ではその親、一覧下の空白ではプロジェクト直下がコピー先です。Windows・接続済みWSLの両方に対応し、複数ファイルやフォルダーの中身もコピーできます。コピー元は保持し、貼り付けと同様にUndo／Redoでまとめて取り消し・復元できます。フォルダーに600 ms重ねると展開し、上下端では一覧を自動スクロールします。Escや領域外でのドロップでキャンセルします。同名項目は上書きしません。

プロジェクトのルートフォルダーも、選択してCtrl+C／`Copy`でコピーし、別プロジェクトへ貼り付けられます。ルートの切り取り・削除はできません。コピー元のフォルダー自身やその配下への貼り付けは拒否します。

Windowsの別プロジェクトへも、フォルダーの階層・空フォルダー・ファイルとフォルダーの更新日時を保ってコピーできます。コピー元はそのまま残り、貼り付け先のプロジェクトでUndo／Redoを行えます。

`tests/resource_copy_tests.cpp`のWindows用テストでは、プロジェクト間のフォルダーコピーと秒未満を含む更新日時の保持を確認します。`tests/folder_tests.cpp`には、フォルダーをコピーして別プロジェクトへ切り替え、貼り付け・選択・Undo／Redoとコピー元の保持を確認するGUIテストがあります。Windows用テストの実行にはWindows環境が必要です。

`tests/explorer_clipboard_tests.cpp`でWSLのUNC別名、接続ユーザー・大文字小文字・日本語の保持、Windows共有との区別、WindowsからWSLへのコピー可否を検証します。Windowsでは実際のクリップボードのコピー／切り取り形式とFile Explorerからの取り込み、OLEドロップのコピー効果・キャンセル・無効なファイル一覧の拒否も確認します。`tests/wsl_helper_tests.cpp`では取り込んだWSLパスから実ファイル・フォルダーとプロジェクトルートをコピーし、Windowsからの取り込みで使うコピー処理のバイナリ・空フォルダー・16 MiB超ファイルの保持とリンク・上書きの拒否も検証します。`tests/folder_tests.cpp`ではルートのコピー・貼り付け・Undo／Redoと切り取りの抑止を確認します。クリップボードとGUIの実行検証にはWindows環境が必要です。

複数選択した削除・貼り付け・ドラッグ移動は、1回のUndo／Redoでまとめて取り消し・やり直しできます。途中で失敗した場合は完了済みの項目だけを履歴に残し、エラーを表示します。Undo／Redoの途中で同名衝突などが起きた場合も、完了済みの変更を保持し、残りを再試行できます。

EXPLORERにフォーカスがあるとき、Ctrl+Zで直前のファイル操作を取り消し、Ctrl+Y／Ctrl+Shift+Zでやり直します。右クリックの`Undo`／`Redo`からも操作できます。移動・名前変更・コピー・ファイル／フォルダーの新規作成と削除・画像貼り付けが対象です。履歴はプロジェクトごとに直近1,000操作を保持し、プロジェクトを閉じるまで有効です。エディターや名前入力欄のUndo／Redoは、それぞれの本文を対象とします。

EXPLORERでファイルやフォルダーを1つ以上選択してDeleteキー、または右クリック → `Delete`で削除します。空でないフォルダーを含む場合は、`Cancel`／`Delete`の確認ダイアログを表示します。初期選択は`Cancel`で、Escやダイアログを閉じた場合も削除しません。複数選択では全項目の削除をまとめて確認し、キャンセル時はすべて保持します。折りたたんだフォルダーや隠し項目も実際の内容で判定し、ファイルと空フォルダーは確認なしで削除します。フォルダーは中身もまとめて削除し、プロジェクトのルートは対象外です。Windows・接続済みWSLの両方で利用でき、Ctrl+Zで復元、Ctrl+Yで再び削除できます。名前入力欄やエディターのDeleteキーは、その欄の文字を削除します。

新規作成のUndoと削除は、対象のファイルやフォルダーを内容・属性ごとプロジェクトの親フォルダーの`.poppy-undo-<ID>`へ退避し、新規作成のRedoまたは削除のUndoで戻します。新たに作成した中間フォルダーもまとめて取り消し、既存の親フォルダーは残します。開いたタブと未保存本文は保持し、ファイルが戻るまで保存はできません。退避先の書き込み権限不足、別ファイルシステムへの移動、同名衝突などで失敗した場合は上書きせず、履歴を残してエラーを表示します。Redoを残した状態で新しい操作を行うと不要な退避データを削除します。削除済みの項目は、履歴上限を超えて復元できなくなるか、プロジェクトを閉じると退避データも削除します。ごみ箱は使いません。異常終了や削除失敗時には退避データが残る場合があります。

`tests/tree_tests.cpp`で範囲選択・選択の追加／解除・親子の重複除外を、`tests/resource_copy_tests.cpp`で実ファイル・フォルダーのコピー、16 MiB超のファイル、リンク・同名衝突・循環の拒否と一時データの後片付けを検証します。`tests/explorer_history_tests.cpp`で複数項目の取り消し／復元・途中失敗時の再試行と、ファイル・フォルダーの取り消し／復元、内容の保持、衝突時の再試行、Redoの破棄と履歴上限を、`tests/wsl_helper_tests.cpp`でWSLの実ファイル、属性・リンクの保持、復元後の保存、リンク先を削除しない退避データの削除を検証します。`tests/folder_tests.cpp`にはショートカット、Deleteキーによる削除と復元、空でないフォルダーの確認とキャンセル・複数選択の保持、空フォルダーの確認なし削除、ルートの保護、削除失敗時の保持、ツリー・タブ・未保存本文の追従、中間フォルダーと画像の取り消し／復元を確認するWindows用GUIテストがあります。このGUIテストの実行にはWindowsのデスクトップ環境が必要です。

EXPLORERの選択したファイルやフォルダーは、同じプロジェクト内の別のフォルダーへ左ドラッグでまとめて移動できます。移動先の行が強調表示されたらマウスを離してください。ルートの行や一覧下の空白へのドロップでプロジェクト直下へ移動します。フォルダーに600 ms重ねると展開し、一覧の上下端では自動スクロールします。Esc、キャプチャ喪失、領域外へのドロップでキャンセルします。プロジェクトのルート自身、自分自身や配下、現在の親、リンク／ジャンクションのフォルダーへの移動はできません。同名の項目がある場合は上書きせずエラーを表示します。Windows・接続済みWSLの両方で利用でき、開いたタブ・未保存本文の保存先・ツリーの展開状態も追従します。

移動は`tests/tree_tests.cpp`で階層・兄弟順・展開と選択の保持、循環や不正な移動の拒否を、`tests/wsl_helper_tests.cpp`で実ファイル・フォルダーの移動、日本語・空白・バックスラッシュを含む名前、同名衝突・古い版・不正な移動先・リンクの拒否と移動後の保存を検証します。`tests/folder_tests.cpp`にはクリックとドラッグの区別、キャンセル・無効な移動、タブと未保存本文の保持、移動先への保存、衝突時のエラー、再起動後の復元を確認するWindows用GUIテストがあります。GUI操作の実行検証にはWindowsのデスクトップ環境が必要です。

Ctrl+NでEXPLORERに切り替え、新しいファイルのパスを入力できます。選択したフォルダー内、ファイル選択時はその親、選択がなければプロジェクトのルートが作成先です。エディター・ツリーから使えます。EXPLORERのファイルやフォルダー（プロジェクトのルートを含む）の右クリック → `New File…` / `New Folder…`からも作成できます。ファイルの右クリックでは、そのファイルと同じフォルダー内に作成します。

新規作成を始めると作成先のフォルダーを展開し、選択したファイルやフォルダーのすぐ次の行へ入力欄を挿入します。右クリックからの作成も、クリックした項目の直後に表示します。ファイル選択時はそのファイルと同じ字下げ、フォルダー選択時は子項目と同じ字下げになります。既存の項目名はそのまま残り、後続の項目だけを1行ずらします。入力欄が画面下端に収まらないときは、入力欄が見える位置までスクロールします。入力欄でEnterを押すと作成し、Escや入力欄の外へのフォーカス移動でキャンセルします。`path/to/file.md`は不足する中間フォルダーも作成します。末尾が `/` の `path/to/folder/` はフォルダーを作成します。区切りはWindows・WSLとも `/` を使い、絶対パス、`.`、`..`、空のパス要素は受け付けません。入力は最大4,096文字、各要素はWindowsでは255文字、WSLでは255 UTF-8バイトまでです。既存の中間フォルダーは利用し、最後の同名ファイルやフォルダーは上書きしません。作成後は親フォルダーを展開して新しい項目を選択し、ファイルはエディターで開きます。Windows・接続済みWSLの両方で利用できます。リンク／ジャンクションを中間フォルダーとして使うことはできません。作成が途中で失敗した場合、それまでに作成した中間フォルダーは残ります。

新規作成の入力位置・多数のファイルがあるフォルダーでの先頭／中間／末尾への挿入・既存項目との重なり防止・フォルダー読み込み中の入力維持・確定とキャンセル・挿入元の削除や折りたたみ・DPIと幅の変更・画面下端でのスクロールは`tests/render_tests.cpp`で、Ctrl+Nと右クリックメニューからの入力位置・字下げと実際の作成先は`tests/folder_tests.cpp`で検証します。ファイルの右クリックからの作成は、ルート直下と子フォルダー内の両方で、同じ階層へのファイル・フォルダー作成と作成後の選択・タブを確認します。これらのGUIテストの実行にはWindowsのデスクトップ環境が必要です。

クリップボードに画像があるとき、EXPLORERでCtrl+V、または右クリック → `Paste Image`でPNGを新規作成します。選択したフォルダー内、ファイル選択時はその親、空白部分の右クリックではプロジェクトのルートに保存します。名前はローカル時刻の `paste-yyyy-MM-ddThh-ii-ss.png`（24時間表記、`ii`は分）です。同じ秒の同名ファイルがあれば上書きせずエラーを表示します。作成後はフォルダーを展開し、新しい画像を選択します。作成したPNGを開くと画像をプレビューできます。

Windows・接続済みWSLの両方で利用できます。PNG形式とWindowsのDIB／DIBV5形式（スクリーンショット等）に対応し、クリップボードと展開後の画素は64 MiB、PNGファイルは16 MiBまでです。画像の変換と保存はバックグラウンドで行います。ファイルのクリップボードがあるときはファイルの貼り付けを優先します。テキストの貼り付けはEXPLORERでは扱いません。

EXPLORERのファイル／フォルダー（プロジェクトのルートを含む）やファイルのタブを右クリック → `Reveal in File Explorer`で、WindowsのFile Explorer（explorer.exe）に対象を選択して表示します。空白や日本語を含むパスにも対応します。WSLは`\\wsl.localhost`経由で表示し、Windows側のWSL共有のアクセス権を使います。名前にバックスラッシュを含むWSLパスは表示できません。コミット時点のファイルや`All Changes`のタブには、この項目を表示しません。表示に失敗するとエラーを表示します。

ファイルのタブの`Copy Path` / `Copy Relative Path`は、通常ファイル・個別のGit差分・コミット時点のファイルで使えます。Windowsでは区切りに`\`、WSLでは`/`を使い、WSLの絶対パスはLinux側のパス（例: `/home/user/project/src/main.cpp`）になります。相対パスの基準は、複数のGitリポジトリがある場合も開いているプロジェクトです。非選択タブからもコピーでき、表示中のファイルは切り替わりません。`All Changes`には表示しません。

`tests/session_tests.cpp`で通常・Gitタブ、日本語・空白・WSLのパス、プロジェクトを基準とした相対パスと集約タブの除外を検証します。`tests/folder_tests.cpp`には非選択タブ・固定タブからのコピーと表示中のファイルの保持を確認するGUIテストがあります。GUIテストの実行にはWindows環境が必要です。

エクスプローラーのファイルやエディターのタブを右クリック → `Open with Default Application`で、Windowsに関連付けられたアプリケーションで開きます。ディスク上のファイルを開くため、Poppyでの未保存の編集は先にCtrl+Sで保存してください。起動に失敗するとWindowsのエラーを表示します。

ファイルやフォルダーを選んでF2、または右クリック → Renameを選びます。名前はツリーの文字位置で直接編集し、通常の行と同じフォント・文字色・背景を使います。枠付きのWindows標準入力欄は表示しません。名前を入力してEnterで確定、Escや入力欄の外へのフォーカス移動でキャンセルします。ファイルは拡張子を除く部分を最初に選択します。日本語IME、マウスによる選択、Ctrl+A / C / X / V、Undo / Redoに対応します。プロジェクトのルートフォルダーは変更できません。既存の同名ファイルへの上書きは行いません。

`tests/render_tests.cpp`では名前変更中の文字入力・選択置換・絵文字の削除・貼り付け・Undo、IME変換中のEnter、確定・キャンセル、DPI・幅変更とフォルダー折りたたみへの追従を検証します。100% / 150% / 200%の描画を通常のツリーラベルと画素単位で比較し、フォント・文字色・背景・位置が一致することも確認します。このGUI・描画テストの実行にはWindows環境が必要です。

成功すると開いているタブ、未保存本文の保存先、フォルダー配下のパス、ツリーの展開・選択、ファイル検索とGit一覧を更新します。Terminalの次回起動ディレクトリも追従します。実行中のシェルのカレントディレクトリは変更しません。権限不足や使用中のフォルダーなどの失敗はWindowsのエラーを表示します。
